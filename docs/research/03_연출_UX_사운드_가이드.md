# 03. 연출(演出) · UX · 사운드 가이드

> 대상: 세로(portrait) 2D 캐주얼 전략 게임 — 소환(summon) / 합성(merge) / 자동 공격 / 가챠(gacha) 연출 / 보스 웨이브 / 인런(in-run) 업그레이드 선택 / 메타 쉘(홈·컬렉션·상점·미션·시즌패스)
> 기술 스택 전제: HTML5, PixiJS v8 (WebGL), WebAudio. 논리 해상도 **720×1280**.
> 작성일: 2026-10-06. 조사 방식: 웹 검색 + 1차/2차 자료 열람. 근거 등급을 아래 태그로 분리 표기.

## 0. 이 문서의 읽는 법 (근거 표기 규칙)

| 태그 | 의미 |
|---|---|
| **[S#]** | **출처가 직접 서술한 사실/수치.** `#`는 맨 아래 Sources 번호. 출처가 2차 요약(블로그/검색 스니펫)일 때는 Sources 항목에 그 사실을 적어 둠. |
| **[R]** | **내가 제안하는 권장 시작값.** 출처가 말한 값이 아님. 실기기(미들레인지 폰)에서 튜닝해야 하는 *출발점*. |
| **[C]** | 출처 값에서 내가 **계산**한 파생값(해상도 환산 등). |
| **[U]** | **미검증/출처 상충.** 사용 전에 직접 확인할 것. (목록은 §8) |

**규칙**
- 아래 §2·§5.6 표의 모든 수치는 **별도 태그가 없으면 [R]** 이다. 출처 기반 값은 `비고` 열에 `[S#]`로 표시한다.
- 단위: 시간은 ms, 길이는 **논리 px(720×1280 기준)**, 주파수는 Hz, 게인은 선형(0–1) 또는 dB.
- 1프레임 = 16.7 ms (60 fps), 33.3 ms (30 fps).
- 도박(slot) 연구에서 가져온 기법은 **연출(presentation)** 에만 쓰고, 결과(outcome)는 연출 시작 전에 이미 확정되어 있어야 한다. 유료 가챠는 확률 공개 의무가 있다 (§1.3, [S30a][S30b]).

### 1.2 엔지니어링 원칙 10개 [R]

1. **지연 예산**: 입력 → 첫 변화 ≤ 16 ms 목표, ≤ 100 ms 한계 [S4b]. 소환/합성 버튼은 `pointerdown`에서 즉시 시각·청각 반응.
2. **A/V 동기**: ITU-R BT.1359 기준 오디오가 영상보다 **45 ms 앞서거나 125 ms 늦으면 감지 가능**(허용 한계 +90/−190 ms) [S37]. 모든 SFX는 시각 변화와 **같은 프레임에 스케줄**(`ctx.currentTime + 0`). 블루투스 출력은 지연이 크므로 SFX는 보정하지 않고 `outputLatency`는 음악/영상 정렬에만 사용 [S31e].
3. **Juice 예산**: 중간~높음 > 극단/없음 [S7]. 이벤트 빈도의 역수로 강도 배정(자주 일어날수록 약하게).
4. **에스컬레이션 사다리**: T0–T5 6단계(§2.0). **기저(baseline)를 낮게** 잡아야 정점이 산다.
5. **비차단(non-blocking)**: 연출은 입력을 막지 않는다. 컷인은 총 ≤1.4 s, 탭으로 2× 가속 skip, 같은 유닛 반복 시 단축본(≤600 ms).
6. **3단 구조**: *anticipation(예고) → impact(충격) → settle(안정)*. 예고는 희귀할수록 길게(§2.2, §2.5).
7. **다채널 중복(redundancy)**: 중요 이벤트는 시각+청각(+햅틱)이 **동일 타임스탬프**. 한 채널을 끈 사용자(음소거/모션 감소)도 의미를 얻도록 최소 2채널 유지.
8. **정보를 feel로 전달**: 크기·음정·shake·색이 크기/희귀도/콤보 단계를 **숫자를 읽기 전에** 알려준다.
9. **접근성은 1급 기능**: shake/flash/motion/haptic 토글, 색 외 단서 (§3.7).
10. **성능 가드레일 우선**: 모든 효과는 풀링·상한·품질 단계(§6)를 전제로 설계.

### 1.3 "Slot/가챠 안티시페이션" 기법의 윤리·규제 경계 [R]

- 연출이 길어지는 지점은 "등급은 알았지만 정체를 모르는 틈" [S11]. 이 틈을 **늘리되**, 결과를 바꾸거나 오도하지 않는다.
- Apple App Store Guideline 3.1.1: 랜덤 가상 아이템 유료 구매는 **구매 전에 각 아이템 획득 확률을 공개**해야 함 (2017-12-26 도입) [S30a].
- 한국: 게임산업법 개정으로 **2024-03-22부터** 국내외 모든 사업자가 확률형 아이템 확률을 **구매 화면에 공개**해야 함. 위반 시 시정요구 불이행 때 최대 2천만 원 벌금/2년 이하 징역, 해외 게임은 유통 차단 가능 [S30b].
- 따라서: (a) 가챠 화면에 `확률 보기` 상시 노출 (b) 결과는 연출 시작 전에 확정 (c) 색 에스컬레이션은 최종 등급을 향해서만 상승 (d) 연출 skip 항상 제공.

#### 2.0.2 Easing 이름과 공식 (Penner/easings.net 계열 [S40])

| 이름 | 공식 (t∈[0,1]) | 주 용도 |
|---|---|---|
| `easeOutQuad` | 1−(1−t)² | squash 복귀, 넉백 |
| `easeOutCubic` | 1−(1−t)³ | **UI 기본 out**, 상승 텍스트, 카운트업 |
| `easeInCubic` | t³ | 퇴장, fly-to-HUD 가속, 닫힘 |
| `easeInOutCubic` | t<0.5 ? 4t³ : 1−(−2t+2)³/2 | 카메라 줌, timeScale 복귀 |
| `easeOutQuint` | 1−(1−t)⁵ | 릴 감속, 숫자 롤업 |
| `easeOutExpo` | t=1 ? 1 : 1−2^(−10t) | 배너/컷인 슬라이드 인 |
| `easeOutBack(s)` | 1+(s+1)(t−1)³+s(t−1)² | **팝/오버슈트**. 오버슈트 최대치: s=1.70158→**10%**, 2.0→13%, 2.5→19%, 3.0→25% [C] |
| `easeInBack(s)` | (s+1)t³−s·t² | 예고(anticipation) 당겨짐 |
| `easeOutElastic` | 2^(−10t)·sin((10t−0.75)·2π/3)+1 | 보상 아이콘 등 **제한적**으로만 |
| `easeInOutSine` | −(cos(πt)−1)/2 | 루프 펄스(idle CTA, 위험 비네트) |

**Spring wobble (카드/유닛 "juice_up"류)** [R]: `x(t) = A·e^(−k·t)·cos(2π·f·t)`, 회전 A=8° 또는 스케일 A=0.12, f=9–11 Hz, k=6–7 /s → 350 ms에 ~10% 잔존, 500 ms에 종료. (Balatro 카드 흔들림의 *원리*를 모사. 실제 Balatro 상수는 미확인 [U].)

#### 2.0.3 Shake 모델 (trauma 방식) [R, 개념 출처 S38]

```js
// trauma ∈ [0,1]. 이벤트마다 add, 매 프레임 decay.
// T1 +0.25 / T2 +0.40 / T3 +0.60 / T4 +0.80 / T5 +1.00, decay = 1/지속(s)
trauma = Math.min(1, trauma + add);
// per frame:
trauma = Math.max(0, trauma - dt / duration);
const s  = trauma * trauma;                   // 소형은 s², 대형 날카로움이 필요하면 s³
cam.x   = A    * s * noise(t * 28, 0);        // noise ∈ [-1,1] (Perlin/simplex 또는 sin 합성)
cam.y   = A    * s * noise(t * 28, 100);
cam.rot = Arot * s * noise(t * 28, 200);      // 2D에서는 translate + rotate 병용 [S38]
world.position.set(-cam.x, -cam.y);           // HUD가 아닌 "월드 컨테이너" 하나만 이동
```
Eiserloh(GDC 2016)는 trauma 기반 shake와 2D에서의 이동+회전 병용을 권장 (검색 스니펫 확인) [S38]. **HUD/팝업은 흔들지 않는다**(가독성·접근성).

### 2.2 소환(summon) & 합성(merge)

> **원칙**: 등급 색/링은 **t=0에 즉시 노출**(색-먼저) → 플레이어는 팝 이전에 등급을 안다 [S11]. 소환은 연타되므로 **셀별 독립 타임라인, 비차단**. 등급이 올라갈수록 *예고(anticipation)가 길고, 레이어가 늘고, 오디오 음역이 넓어진다*.

**멀티 뽑기 (10연)** [R, 관찰 S11]: 플레이어는 파밍 중 수백 번의 멀티 뽑기를 skip하고 중요한 배너에서만 본다 [S11] → ① `skip`(우상단 96×96 이상) **항상 노출**, ② 10장을 뒷면 카드로 그리드 배치 후 **180 ms 스태거로 자동 플립**(탭으로 즉시), ③ **총 길이 ≤1.5 s, 단 Legendary 이상이 있으면 그 1장만 풀 연출**, ④ 카드 뒷면 테두리에 등급색을 점진 공개(색-먼저), ⑤ 첫 1회 이후 "연출 간소화" 옵션 기억.

**상자 오프닝(Clash Royale류 / Brawl Stars Starr Drop류)** [R]: 연출 세부는 1차 자료 미확보 [U]. Starr Drop는 탭(최대 4회)마다 등급 상향 *연출*이 있고 등급은 지급 시점에 확정된다는 2차 서술 [S15]. 권장 타임라인: `탭 → 뚜껑 rattle(x ±3 px·rot ±2° @14 Hz, 400 ms, 램프 12→24 Hz)` → `버스트 120 ms` → 아이템 **220 ms 스태거 아치 배출**, 아이템 `pop` 음정 +1 반음씩 상승 → **마지막(최고 가치) 아이템 +1 s 강조**(slow-mo 0.5× 250 ms + 빔).

**슬롯/릴형 연출 레시피** (릴 3개 또는 룰렛) [R, 개념 S13]
- 회전 속도 3600 px/s(심볼 높이 160 px). 릴 i 정지 시각 = `T0 + 700 + i×350 ms`.
- **감속(일반)**: 600 ms `easeOutQuint`. **감속(기대 구간, 앞 두 릴이 일치 가능 상태일 때 마지막 릴)**: **1400 ms `easeOutQuint`** + 마지막 2 심볼은 250 ms/400 ms 간격으로 "기어서" 통과. 실험 과제의 릴 간 SOA는 1.2 s였음 [S13].
- `reel_tick`: 심볼 통과마다 1틱, 속도에 비례(25/s → 3/s), 마지막 틱은 +3 dB·낮은 음. 정지 시 `reel_stop`(thunk) + 릴 y 오버슈트 12 px `easeOutBack(1.7)` 150 ms.
- 당첨 시 `jackpot` (§5.6), **결과는 스핀 시작 전에 확정**.

### 2.7 구현 우선순위 (ROI 순) [R]

### 3.6 팝업 스택 · 재화 바

**팝업 스택 규칙 [R]**
- **모달은 한 번에 1개**. 우선순위 큐: 시스템/에러 > 구매 확인 > 보상 > 프로모. 앱 시작 직후 팝업은 **≤2개**(첫 7일), 첫 세션 0개.
- z-레이어: L0 HUD / L1 화면 / L2 모달 / L3 보상 팝업 / L4 토스트 / L5 튜토리얼 차단 오버레이.
- 닫기: `X`(우상단, 히트 96×96) + 바깥 탭(파괴적 동작 제외) + 뒤로가기. 보상 팝업은 바깥 탭으로 닫히지 않음.
- 중첩 깊이 ≤2. 열림/닫힘 애니는 입력을 막지 않음(U-05/06).

*(5단계 구성이면 Uncommon 제외. "불멸/Immortal" 상위 티어가 필요하면 흰색→프리즘 그라디언트.)*

**색각 이상** [S26, S23]: 남성 약 8%, 여성 약 0.5%가 색각 이상(대부분 적록) — 2차 자료. Game Accessibility Guidelines: "**핵심 정보를 색만으로 전달하지 말 것**"(Basic). → 위 표의 **프레임 형태 + 핍 개수 + (색각 모드에서) 등급 글자 배지 C/U/R/E/L/M**을 항상 병행. Uncommon(초록)과 Mythic(빨강)은 적록 혼동 위험이 있으나 서로 멀리 떨어진 등급이고 휘도·프레임이 다르다. 검증: Chrome DevTools `Rendering → Emulate vision deficiencies`로 확인 [R].

### 3.8 접근성: 모션 · 플래시 · 사운드 · 설정

**WCAG 2.3.1 (Three Flashes or Below Threshold)** [S19]
- 통과 조건: **어떤 1초 구간에도 일반 플래시 ≤3회 및 적색 플래시 ≤3회**, 또는 플래시 면적이 임계 이하.
- general flash = 상대 휘도 최대치의 **10% 이상** 반대 방향 변화 쌍, 어두운 쪽 상대 휘도 <0.80. red flash = R/(R+G+B) ≥0.8인 포화 적색 전이 + CIE 1976 UCS 차이 >0.2.
- 면적 임계 = 10° 시야 내 **0.006 sr (= 10° 시야의 25%)**. 참고: 1024×768에서 **341×256 px** 사각형이 10° 시야의 근사치.
- **[C] 폰 환산**: 시청거리 ≈33 cm에서 10° ≈ 5.8 cm — 폭 6.9 cm 폰의 약 84%. 즉 **풀스크린 flash는 면적 예외를 사실상 못 쓰므로 3회/초 규칙을 지켜야 한다**. 본 가이드는 여유를 두어 **풀스크린 flash ≤2회/초, α≤0.45, 적색 포화 금지**.

**설정 화면 필수 항목 [R]** (Game Accessibility Guidelines: 효과/음성/음악 **볼륨 개별 조절** Basic [S23], 소리 전용 정보는 시각 병행 Basic/Intermediate [S23], 비핵심 요소 skip 제공 Intermediate [S23])
| 설정 | 옵션 | 기본 |
|---|---|---|
| 화면 흔들림 | 끔 / 줄임(×0.35) / 보통 | OS `prefers-reduced-motion`이면 줄임, 아니면 보통 [S24b] |
| 번쩍임 효과 | 끔 / 줄임 / 보통 | 보통 |
| 모션 감소 | 슬로모·줌·패럴랙스·루프 펄스 off | OS 설정 연동 |
| 햅틱 | 끔 / 약 / 보통 (Android만 표시) | 보통 |
| 볼륨 | 마스터 / 음악 / 효과음 / UI 각각 | 0.8/0.5/0.8/0.7 |
| 데미지 숫자 | 끔 / 간략(크리·큰 값만) / 전체 | 전체 |
| 텍스트 크기 | S / M / L | M |
| 색각 보조 | 등급 글자 배지 + 핍 강조 | 끔 |
| 연출 skip | 컷인/가챠 간소화 | 끔 (첫 시청 후 제안) |

`prefers-reduced-motion`은 2020-01부터 광범위 지원 Baseline이며 전정 장애(vestibular) 트리거(큰 객체 확대/패닝)를 줄이라는 근거가 있다 [S24b].

### 3.9 현지화 레이아웃: 한국어 vs 영어

| 주제 | 규칙 [R] (근거 있는 항목은 [S]) |
|---|---|

| 렌더 방식 | **BitmapText는 숫자/영문 전용**. PixiJS 문서는 CJK·이모지엔 `Text`/`HTMLText`를 권장 [S36c]. 한글 UI = `Text`(변경 시에만 갱신·캐시), 데미지 숫자 = BitmapText 숫자 전용 폰트 |
| 숫자 단위 | ko `만(10⁴)/억(10⁸)` (예 `1.2만`, `3.4억`), en `K/M/B` — 포맷터를 로케일별 분리 [R, 일반 지식] |
| 문자열 | 하드코딩 줄바꿈 금지, 키+변수 치환(한국어 어순은 변수 위치가 달라짐), ko는 복수형 없음·en은 `1 gem / 2 gems` |
| 오버플로 | 버튼 라벨 자동 축소 하한 0.75 → 말줄임. 컷인 이름 배너는 축소 우선 |
| 톤 | UI 문구 존댓말 `~해요`체 통일, 보상/에러 문구 길이 상한(2줄) |

## 4. FTUE / 온보딩 (hybrid-casual)

### 4.1 출처가 말하는 것 [S]

- **즉시 재미**: "플레이어는 게임을 열자마자 재미있는 무언가를 해야 한다. 시작 시 광고·페이월·계정 생성을 피하라." [S29b]
- **점진적·맥락적 학습**: 하이브리드 캐주얼 튜토리얼은 단순하게, 메커닉을 작은 단계로 나누고 핵심 메커닉을 최대한 빨리 체험시키라. 반대로 **설명 없이 1분 넘게 자유롭게 두면 혼란과 이탈**이 생긴다 [S29a].
- **광고는 첫 세션 이후**: "첫 세션에서는 게임플레이에 집중, 광고 도입은 몰입한 뒤로 미뤄도 된다" [S29a]. IAP는 참여가 확립된 뒤 도입하되 첫 세션 대부분 전환을 기대하지 말 것 [S29b].
- **측정**: 튜토리얼 단계별 퍼널, 핵심 메커닉 도달 속도, 첫 세션 복귀율 [S29a]. 사례: Trash Tycoon은 최적화 전 **튜토리얼 중 60% 이탈** [S29a]. 가치가 5–15분 내 명확하지 않으면 이탈 (2차 요약) [S29].
- **벤치마크(GameAnalytics Q1 2024, 전체 중앙값)**: D1 **22.91%**, D7 **4.2%**, D28 **0.85%**, 세션 길이 중앙값 **4분 45초**, 하루 4–5세션 [S29c]. (하이브리드 캐주얼 플레이북 요약의 D1/D30 수치는 서로 모순되어 **채택하지 않음 [U]**.)

9. 첫 런 종료 후 **다음 행동이 불명확**(홈에서 무엇을 해야 하는지)
10. 연출이 입력을 막음 (컷인·가챠 skip 불가)

## 5. 오디오 (SFX · 믹스 · 적응형 음악 · WebAudio 함정 · 절차적 합성)

### 5.1 SFX 설계 관례

**출처가 말하는 것 [S]**
- Nuclear Throne: 임팩트 사운드를 **소재(살/식물/바위/금속) × 캐릭터별**로 조합 [S2].
- 반복 피로의 근본 원인은 "하나의 샘플을 변주 없이 반복 트리거"하는 것 — 해법은 **랜덤 샘플 변형 + 피치/볼륨 변조 + 라운드 로빈** [S33].
- 보이스 쿨다운은 FMOD에 기본 제공, Wwise는 시퀀스 컨테이너+무음 길이+"Discard newest instance" 우회로 구현하는 것이 흔한 패턴 [S33].
- 점수가 쌓일 때 **상승 음정**(5장=C-D-E-F-G)과 곱 트리거용 "ka-ching" 레이어, 임계 도달 시 베이스 드롭 — 3자 분석, 개발자 발언 아님 [S10].

**권장 관례 [R]**
| 항목 | 규칙 |
|---|---|
| 길이 | UI 20–150 ms, 타격 30–200 ms, 보상 300–1500 ms, 팡파레 ≤2.5 s |
| 레이어링 | L1 transient(5–30 ms) + L2 body(80–300 ms) + L3 tail(300–1500 ms) + L4 musical + L5 sub. **작은 이벤트는 L1+L2만**, 큰 이벤트일수록 레이어 추가 |
| 변주 | 빈번한 SFX는 **3–5 변형** + 피치 ±3–8% + 게인 ±1 dB, **직전과 같은 변형 연속 금지** |
| 음정 사다리 | 반음 비율 `2^(1/12)=1.0595`. 보상·콤보·틱 음은 **게임 조성(예: C 메이저 펜타토닉)** 으로 양자화해 음악과 어울리게 |
| 주파수 배분 | 빈번 SFX는 300 Hz–3 kHz 중심. **>4 kHz 고음 반짝임은 희귀 이벤트 전용**. 서브(30–80 Hz)는 T3+ 이벤트만 |
| 정적 박(silence beat) | 큰 보상 직전 **150–250 ms 감쇠/무음**(Legendary 가챠 −15 dB) → 임팩트 대비 극대화 |
| 덕킹 | 이벤트 등급별 음악 duck −2…−10 dB (§2.0.1), 어택 80 ms / 홀드 이벤트 길이 / 릴리즈 500–1200 ms |
| 피치 변경 금지 대상 | UI·팡파레·차임(음악적 정확성 필요) — 랜덤화는 타격/죽음/코인류에만 |

### 5.2 버스 구조 · 라우드니스 · 믹스 레벨

**출처가 말하는 것 [S]**: 모바일 게임은 대중교통 등 소음 환경과 약한 내장 스피커를 고려해 **loudness range를 5–10 LU로 좁게** 가져가야 한다 [S32a]. 모바일 타깃 **−16 LUFS** 가 TC Electronic 연구에서 적절하다고 보고되었고, iTunes Soundcheck −16.2 LUFS, Sony 모바일 −18 LUFS가 언급된다 [S32b](2차·검색 스니펫). True peak 모바일 표준은 확인 못함 **[U]**.

**권장 [R]**
```
musicBus ─┐
sfxBus  ──┼─> masterGain ─> DynamicsCompressor(limiter 역할) ─> destination
uiBus   ──┘
```
| 버스 | 기본 gain | 평균 피크(마스터 전) | 비고 |
|---|---|---|---|
| music | 0.50 | −12 dBFS | 이벤트 duck 대상 |
| sfx | 0.80 | −14 dBFS (빈번), −8 dBFS (보상), −3 dBFS (T4–T5) | 보이스 리미터 적용 |
| ui | 0.70 | −16 dBFS | 항상 duck 제외 |
| master | 0.90 | — | 설정 슬라이더 |

- `DynamicsCompressorNode`(마스터): threshold −12 dB, knee 10, ratio 8, attack 0.003 s, release 0.15 s [R] (스펙 기본값 −24/30/12/0.003/0.25 대비 리미터에 가깝게 조정).
- **목표**: 평균 −16 LUFS 근방, LRA 5–10 LU, 순간 피크는 −1 dBFS 이하. 런타임 LUFS 측정은 어렵다 → **에셋 파이프라인에서 `ffmpeg -af loudnorm=I=-16:TP=-1.5:LRA=8`로 정규화**, 절차적 SFX는 프리렌더 후 **RMS 정규화(빈번 −20 dBFS, 보상 −16 dBFS) + 피크 −3 dBFS** [R].
- 모바일은 소음 환경 → 중요 이벤트 정보는 소리만으로 전달하지 않는다(시각 병행, §3.8).

```js
const last = new Map(), live = new Map();
function canPlay(id, cool, max) {
  const now = performance.now();
```

### 5.4 적응형 음악 (웨이브/보스 강도)

**출처가 말하는 것 [S]**: 수직 레이어링(vertical layering)은 동일 템포·조성·구조의 **스템을 동시에 재생하며 볼륨으로 가시성 제어**; 수평 리시퀀싱은 구간 재배열; 실무에서는 두 기법 + **스팅어(stinger)로 이음새 가리기 + 비트에 양자화된 크로스페이드**를 결합 [S34](2차·검색 스니펫).

```js
// "탭하여 시작" pointerup 핸들러 내부(동기 호출)
function initAudio() {
  if (ctx) return;
  ctx = new (window.AudioContext || window.webkitAudioContext)({ latencyHint: 'interactive' }); // sampleRate 지정 금지
  buildBuses();                                              // music/sfx/ui → master → compressor → destination
  try { if (navigator.audioSession) navigator.audioSession.type = 'playback'; } catch {}
  const s = ctx.createBufferSource(); s.buffer = ctx.createBuffer(1, 1, 22050); s.connect(ctx.destination); s.start(0); // 무음 unlock
  ctx.resume();
  ctx.onstatechange = () => { if (ctx.state !== 'running') armOneShotResume(); };
  document.addEventListener('visibilitychange', () => document.hidden ? ctx.suspend() : ctx.resume());
}
```

### 5.6 절차적(procedural) SFX 합성 레시피

#### 5.6.2 WebAudio 렌더러 · 프리렌더 · 재생 스켈레톤

```js
// 레시피(데이터) → 노드 그래프. OfflineAudioContext로 부팅 시 AudioBuffer로 프리렌더 권장.
let noiseBuf;
const getNoise = (ctx) => noiseBuf && noiseBuf.sampleRate === ctx.sampleRate ? noiseBuf : (noiseBuf = (() => {
  const b = ctx.createBuffer(1, ctx.sampleRate, ctx.sampleRate), d = b.getChannelData(0);
  for (let i = 0; i < d.length; i++) d[i] = Math.random() * 2 - 1; return b; })());

// L = { type:'sine|square|sawtooth|triangle|noise', f:[f0,f1?], sweep:ms, env:[A,D,S,R] ms, hold:ms,
//       g:peak, filt:{type,f:[f0,f1?],q}, t:startDelay ms, detune:cents }
function layer(ctx, dest, L, base = 0) {
  const t0 = ctx.currentTime + base + (L.t || 0) / 1000;
  const [A, D, S, R] = [L.env[0] / 1000, L.env[1] / 1000, L.env[2], L.env[3] / 1000];
  const hold = (L.hold || 0) / 1000, end = t0 + A + D + hold + R;
  const g = ctx.createGain(), p = g.gain, su = Math.max(L.g * S, 1e-4);
  p.setValueAtTime(1e-4, t0);
  p.linearRampToValueAtTime(L.g, t0 + A);                    // Attack
  p.exponentialRampToValueAtTime(su, t0 + A + D);            // Decay (exp)
  p.setValueAtTime(su, t0 + A + D + hold);                   // Sustain hold
  p.exponentialRampToValueAtTime(1e-4, end);                 // Release (exp, 0 불가)
  let src;
  if (L.type === 'noise') { src = ctx.createBufferSource(); src.buffer = getNoise(ctx); src.loop = true; src.start(t0, Math.random() * 0.9); }
  else {
    src = ctx.createOscillator(); src.type = L.type; src.frequency.setValueAtTime(L.f[0], t0);
    if (L.f[1]) src.frequency.exponentialRampToValueAtTime(L.f[1], t0 + (L.sweep ?? (A + D) * 1000) / 1000);
    if (L.detune) src.detune.value = L.detune;
    src.start(t0);
  }
  let n = src;
  if (L.filt) {
    const f = ctx.createBiquadFilter(); f.type = L.filt.type; f.Q.value = L.filt.q ?? 0.7;
    f.frequency.setValueAtTime(L.filt.f[0], t0);
    if (L.filt.f[1]) f.frequency.exponentialRampToValueAtTime(L.filt.f[1], end);
    n.connect(f); n = f;
  }
  n.connect(g); g.connect(dest); src.stop(end + 0.02); src.onended = () => g.disconnect();
}

// 프리렌더: 레시피 1개 = Offline 1회 (모노). 총 ≈ 40레시피 × 0.4 s × 48 kHz × 4 B ≈ 3 MB [C]
async function prerender(recipe, sr, durMs) {
  const oc = new OfflineAudioContext(1, Math.ceil(sr * durMs / 1000), sr);
  recipe.layers.forEach((L) => layer(oc, oc.destination, L));
  return oc.startRendering();
}
// 재생: 피치 랜덤 ±0.5 반음 ≈ ±3%
const rate = (semi = 0, spread = 0.5) => 2 ** ((semi + (Math.random() * 2 - 1) * spread) / 12);
function play(id, { semi = 0, spread = 0.5, vol = 1, bus = sfxBus } = {}) {
  if (!canPlay(id, COOL[id], MAX[id])) return;          // §5.3 (쿨다운 + 동시 수)
  live.set(id, (live.get(id) || 0) + 1);
  const s = ctx.createBufferSource(), g = ctx.createGain();
  s.buffer = BUF[id]; s.playbackRate.value = rate(semi, spread); g.gain.value = vol;
  s.connect(g); g.connect(bus); s.start();
  s.onended = () => { g.disconnect(); live.set(id, live.get(id) - 1); };
}
```
- **프리렌더 권장 이유**: 런타임 CPU·노드 수 절감, 재생마다 동일 지연. 부팅 시 레시피별 3–5 변형(파라미터 ±5%)을 만들어 라운드 로빈 [R]. 프리렌더는 유휴 시간에 분산(Safari는 `requestIdleCallback` 미지원 → `setTimeout`) **[U]**.
- **ZzFX 방식(JS에서 샘플 배열 직접 계산 후 AudioBuffer에 복사)** 도 대안: 코드가 작고 sfxr 프리셋 이식이 쉽다 [S35]. 단 메인 스레드 계산 부하 → 부팅 시 1회.
- **ZzFX/jsfxr → 본 표 매핑 요령**: 코인 = `pitchJump`+`pitchJumpTime`으로 2음, 폭발 = `noise` 파라미터↑ + 긴 `release` + `slide` 음수, 팝 = 짧은 sine + 양의 `slide`, 8-bit 질감 = `bitCrush`. 구체 배열값은 ZzFX Sound Designer에서 청취하며 튜닝(파라미터 의미 전체는 README에 상세 없음) **[U]**.

### 6.1 출처(PixiJS 공식 문서)가 말하는 것 [S36]

| 일반 | "필요할 때만 최적화". 씬 복잡도가 오를수록 성능 하락. **같은 타입끼리 묶으면(sprite/sprite/graphic/graphic) 교차(sprite/graphic/sprite)보다 빠름**. 구형 모바일은 `useContextAlpha:false`, `antialias:false` 옵션 권장. **culling은 기본 꺼짐**, `cullable=true`는 GPU 병목에 유리하나 CPU 병목엔 오히려 불리 |

| Graphics | **100 포인트 이하이면 배치됨**, 자주 수정하지 않을수록 빠름. 복잡한 Graphics 수백 개는 느림 → Sprite 사용 |
| Texture | Texture GC가 관리, 수동 `destroy()` 가능. 대량 파괴 시 **랜덤 딜레이**로 프리즈 방지 |
| Text | 프레임마다 변경 금지(캔버스 렌더+GPU 업로드 비용). **동적 텍스트는 BitmapText가 훨씬 낫다**. `resolution` 낮춰 메모리 절감 |
| Mask | 수백 개 마스크는 매우 느림. **사각형(scissor) > Graphics(stencil) > Sprite 마스크(필터, 매우 비쌈)** |
| Filter | 비쌈. 사용 후 `container.filters = null`로 해제, 크기를 알면 `filterArea` 지정 |
| BlendMode | 블렌드 모드가 바뀌면 배치가 끊김(교차 4 draw call vs 묶음 2 draw call) |
| Events | 상호작용 자식이 없으면 `interactiveChildren=false`, `hitArea` 지정으로 이벤트 탐색 절감 |
| ParticleContainer (v8) | 경량 `Particle`(texture, x, y, scaleX/Y, rotation, tint, alpha) — "Sprite보다 훨씬 효율적", "수십만~수백만 파티클". `dynamicProperties`로 프레임마다 GPU에 올릴 속성 선택(기본 position만; rotation/vertex/color는 켜야 동적). **addChild 불가·필터·이벤트 불가**, `addParticle/removeParticle` 사용 [S36b] |
| BitmapText (v8) | 미리 만든 글리프 아틀라스 사용 → 텍스트 변경 비용 매우 낮음(수만 개 가능). `resolution`은 BitmapFont에서 결정, **CJK/이모지는 `Text`/`HTMLText` 권장**. MSDF/SDF 지원 [S36c] |
| Application | `resolution`(기본 1), `autoDensity`, `antialias`(성능 영향), `powerPreference`, `preference`('webgl' 또는 'webgpu', 기본 webgl). 모바일: **고DPI에서 resolution 낮추기, antialias 끄기** [S36d] |

### 6.3 배칭 · 레이어 구성 [R]

```
stage
 ├─ world (shake 대상 컨테이너 1개 — 개별 스프라이트를 흔들지 않는다)
 │   ├─ ground/background        (atlas A, normal)

 │   ├─ projectiles              (atlas B, normal)
 │   ├─ fx_normal  (ParticleContainer, atlas C, normal)
 │   ├─ fx_add     (ParticleContainer, atlas C, blend 'add')   ← 블렌드 그룹 1개

```
- **같은 (아틀라스, 블렌드)끼리 연속 배치**하여 draw call을 줄인다 [S36]. 블렌드 모드 교차 금지.

### 6.5 오브젝트 풀링 · GC 회피 [R]

- **풀 대상**: 투사체, 데미지 숫자, 파티클/FX 스프라이트, 임팩트 링, 토스트, 리스트 아이템, tween 객체. 풀 `acquire()`는 `visible=true`+상태 초기화, `release()`는 `visible=false`(+`renderable=false`). **인런 중 `destroy()`/`new Sprite()` 금지** (공식 문서도 대량 destroy 시 프리즈 주의 [S36]).
- **프레임당 할당 0**: 객체/배열 리터럴, 클로저(`() =>`), 템플릿 문자열, `new Point/Rectangle`, `Array.filter/map/splice` 금지. 재사용 버퍼 + `for` 루프 + **swap-remove**.
- 파티클 상태는 **TypedArray (SoA)**: `x[], y[], vx[], vy[], life[], tint[]` → ParticleContainer의 `Particle`에 값만 복사.
- 이징은 **LUT(256 샘플)** 또는 순수 함수, tween은 **직접 만든 경량 매니저**(풀링, 콜백 최소화). 범용 tween 라이브러리를 이벤트마다 새로 생성하지 않는다.
- **고정 타임스텝**(예: 60 Hz 시뮬 + 누적기), `ticker.deltaMS`를 **50 ms로 클램프**(탭 복귀 시 스파이럴 방지). hit-stop/slow-mo는 `sim.timeScale`에만 적용(§2.0.4).
- 데미지 숫자 문자열: 정수 → 문자열 변환 캐시(0–9999), K/M 변환은 사전 계산.
- 숨김 시: `visibilitychange`에서 ticker 정지 + 오디오 suspend (§5.5).

### 6.6 적응형 품질 거버너 [R]

```
frameMsEMA (120프레임 지수이동평균)
 > 20 ms (≈<50fps)가 3 s 지속 → 한 단계 하향(High→Mid→Low): resolution, particleCap, dnCap, 필터 off
 < 14 ms가 10 s 지속 & 마지막 변경 후 30 s 경과 → 한 단계 상향 (히스테리시스)
선택 단계는 localStorage에 try/catch로 저장 (실패해도 동작)
```
- 하향 우선순위: ① 파티클 상한 ② resolution (2→1.5→1.25→1.0) ③ 데미지 숫자 상한 ④ 글로우/additive 레이어 ⑤ 배경 패럴랙스 ⑥ 30 fps 캡.
- `powerPreference`는 힌트일 뿐(모바일 단일 GPU) — 기본값 유지 [S36d].
- 측정: Android는 `chrome://inspect` 원격 디버깅 + Performance 패널(Minor GC 막대, long task), iOS는 Safari Web Inspector 타임라인; draw call은 Spector.js 등 WebGL 캡처 도구 [R].

## 8. 미검증 · 한계 (사용 전 확인)

1. **Lucky Defense / Random Dice / Vampire Survivors / Survivor.io / Clash Royale 상자 / Genshin 위시 타이밍**: 공개된 1차 디자인 토크·분석을 찾지 못함. 해당 게임 관련 서술은 3자 분석 또는 커뮤니티 수준이고, **정량 연출값은 전부 [R]**.
