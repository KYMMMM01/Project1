# 구글 플레이 첫 출시 흐름

2026-11-10 기준으로 정리했다. 개인 개발자 계정을 막 만든 상태에서 냥이 수비대를 Capacitor 앱으로 구글 플레이에 처음 올리는 순서다. 구글 정책과 법은 바뀌므로 각 단계의 출처를 그 단계를 할 때 한 번 더 연다. "확인 필요"라고 적은 것은 이번 조사에서 원문으로 확정하지 못한 것이다.

## 한눈에 보는 일정

가장 긴 구간은 개인 계정에 걸리는 비공개 테스트 14일이다. 그래서 첫 AAB 를 최대한 빨리 비공개 테스트 트랙에 올리고, 14일이 흐르는 동안 나머지(스토어 등록정보, 앱 콘텐츠 설문, 광고와 결제 연결 확인)를 채운다.

| 주 | 할 일 |
|---|---|
| 1주 | 계정 본인 인증과 기기 인증, 앱 코드의 Capacitor 연결, 첫 서명 AAB, 내부 테스트로 내 폰에서 확인, 비공개 테스트 시작(테스터 12명 이상) |
| 2주에서 3주 | 테스터 유지, 스토어 등록정보, 개인정보 처리방침 게시, 데이터 보안, 콘텐츠 등급, 타깃층, 광고 선언, AdMob 과 인앱 상품 만들기, 테스트 결제 |
| 3주 끝 | 14일을 채우면 프로덕션 액세스 신청(심사 보통 7일 이내) |
| 4주 | 승인 뒤 프로덕션 출시, 첫 주는 충돌률과 ANR, 리뷰, 광고와 결제를 매일 본다 |

계정 인증이 끝난 날부터 빨라도 3주에서 4주가 걸린다.

- 환불 감지(첫 출시는 이대로, 매출을 보고 다시 판단).

1. 앱 패키지 이름(appId): `com.bulssistudio.meowguard` 로 정했다(2026-11-11, 개발자 이름 Bulssi Studio 와 맞춤). 한 번 올리면 영원히 못 바꾼다.
2. 앱 이름. 지금 manifest 는 "냥이 수비대"(영문 Meow Guard). 같은 이름의 앱이나 상표가 있는지 플레이 검색과 KIPRIS(특허정보검색)로 확인한다.
3. 출시 국가. 한국만(또는 EEA, 영국 제외)으로 시작하면 UMP 없이 나갈 수 있다. 전 세계로 가면 UMP 를 먼저 넣어야 한다.
4. 타깃 연령. 귀여운 고양이 게임이라 아동용으로 보일 위험이 있다. 13세 이상(아동 연령층 미선택)을 권한다. 아동을 포함하면 Families 정책이 걸려 맞춤 광고가 막히고 광고 SDK 제약이 커진다. 한국 개인정보 보호법은 만 14세 미만에 법정대리인 동의를 요구하므로 13에서 15 구간을 넣을지도 같이 정한다.
5. 사업자등록과 통신판매업 신고(아래 4단계).
6. 인앱 상품 ID 최종본(아래 8단계). 한 번 만든 ID 는 지워도 다시 못 쓴다.

## 1단계. 개발자 계정 인증

- 등록비 25달러(1회, 선불카드 불가), 만 18세 이상.
- Play Console 의 설정, 계정 세부정보에서 본인 인증을 끝낸다. 결제 프로필의 이름과 주소를 신분증과 똑같이 맞춘다(영문 표기 포함). 틀리면 반려되고 등록비는 돌려주지 않는다.
- 안드로이드 폰에 Play Console 앱을 설치해 기기 인증을 한다(신규 개인 계정은 이것이 있어야 게시 가능).
- 개발자 전화번호를 +82 형식으로 넣고 OTP 인증. 한국 개인 계정은 전화번호가 없으면 게시가 막힌다. 개인 계정은 주소와 전화번호가 공개될 수 있으니 공개해도 되는 것을 쓴다.
- 판매자 상태 선언(EEA, 영국 법): 신규 계정은 만들 때 바로 제출한다. 계정 관리, 계정 세부정보, 내 정보.

## 2단계. 안드로이드 앱 빌드(Capacitor)

코드 쪽은 끝났다(2026-11-11). 사람이 할 일은 Android Studio 설치와 빌드다.

끝난 것
- Capacitor 8 과 플러그인 설치, `capacitor.config.ts`(`webDir: 'dist-store'`, 기본 `dist` 는 소리판 후보 6.8 MB 가 있어 쓰면 안 된다).
- 플러그인 연결(`src/platform/adapters/capacitor.ts`): 설치된 플러그인 타입 정의와 맞춰 확인했다. 맞추면서 고친 것: 첫째, RevenueCat 의 `getProducts` 는 안드로이드에서 기본이 구독 상품이라 일회성 상품 11종이 안 보일 뻔했다(이제 NON_SUBSCRIPTION 으로 묻는다). 둘째, 결제 직후 앱이 죽거나 플레이가 결제를 보류했다가 나중에 확정하면 보석이 지급되지 않을 수 있었다(이제 구매 시작을 기록해 두고 다음 동기화에서 한 번 지급한다). 셋째, 광고 SDK 시작이 첫 화면을 붙잡지 않게 했고, 오프라인으로 켜서 광고 동의 확인이 실패하면 30초마다 다시 묻는다.
- `android/`: targetSdk 36, 세로 고정, AdMob 앱 ID 자리와 release 검사, `android/keystore.properties` 가 있으면 그 키로 서명, 키 파일은 git 제외, Android 12 이상 스플래시 바탕도 크림색.

할 일
1. Android Studio 설치(2025.2.1 이상, JDK 와 SDK 가 같이 깔린다). 설치 중 Android SDK Platform 36 을 고른다.
2. 웹 빌드를 고친 뒤에는 매번 `npm run build:store` 다음 `npx cap sync android`.
3. `npx cap open android` 로 Android Studio 에서 연다(처음 열 때 Gradle 동기화에 몇 분 걸린다).
4. 내 폰을 USB 디버깅으로 연결해 실행(Run). 이때는 debug 빌드라 테스트 광고만 나온다. 단, `.env.store` 에 실제 광고 단위 ID 를 넣은 상태로 debug 를 설치하면 실제 광고가 나오니, 내 폰에서 시험할 때는 `VITE_ADMOB_TESTING=1` 을 같이 넣거나 실제 ID 를 넣기 전에 시험한다. 내 폰에서 실제 광고를 누르면 AdMob 계정이 정지될 수 있다.
5. 확인할 것은 아래 "실기기 점검표". 특히 뒤로가기(지금은 Capacitor 기본 동작: 화면 기록이 있으면 뒤로, 없으면 앱 종료)와 위아래 안전 영역(targetSdk 36 은 edge to edge 강제), 오래된 기기에서 빈 화면이 안 나는지(빌드가 es2020 이라 Chrome 80 미만 WebView 는 안 될 수 있다).
6. Android 16 은 태블릿 같은 큰 화면에서 세로 고정을 무시하고 가로로도 돌린다. 게임은 세로 화면 비율로 그려지므로 가로에서는 좌우가 비어 보일 수 있다. 태블릿이 있으면 한 번 본다.
- 출처: capacitorjs.com/docs/android, capacitorjs.com/docs/getting-started/environment-setup, support.google.com/googleplay/android-developer/answer/11926878

## 3단계. 서명과 AAB

- Android Studio 의 Build, Generate Signed Bundle/APK, Android App Bundle 에서 업로드 키스토어를 새로 만든다(유효기간 25년 이상).
- 키스토어 파일과 비밀번호를 저장소 밖 두 곳 이상(비밀번호 관리자와 외부 저장소)에 백업한다. 잃어버리면 Play Console 에서 업로드 키 재설정을 요청해야 한다.
- 서명을 매번 대화상자로 하지 않으려면 `android/keystore.properties` 를 만든다(git 에 안 올라간다): `storeFile=`(android 폴더 기준 경로나 절대 경로), `storePassword=`, `keyAlias=`, `keyPassword=`. 네 줄이 다 있으면 `bundleRelease` 가 그 키로 서명한다.
- `versionCode` 는 1 부터 올릴 때마다 1씩, `versionName` 은 사용자에게 보이는 값. 둘 다 `android/app/build.gradle` 에 있고 지금 1 과 1.0.0 이다.
- 첫 업로드 때 Play App Signing(신규 앱 필수)에 동의하고 구글이 만드는 앱 서명 키를 고른다.
- 출처: developer.android.com/studio/publish/app-signing

## 4단계. 사업자등록, 통신판매업, 세금(한국)

- 구글 안내(answer/3255733): 업체는 주소와 전화번호, 개인은 전화번호만 낸다. 유료 앱이나 인앱 구매가 있는 앱을 배포하는 한국 "업체"는 사업자등록번호, 통신판매업 신고번호, 신고 기관(시군구청)을 계정 세부정보의 업체 문의 연락처에 넣고, 이것이 한국 사용자에게 앱 설명 아래 표시된다. 문구의 주체가 업체라 개인 계정에도 요구되는지는 문서가 말하지 않는다. Play Console 입력 화면의 필수 표시로 확인 필요.
- 통신판매업 신고 면제: 공정위 고시로 직전 연도 거래 50회 미만이거나 간이과세자이면 면제(2020년 도입). 현행 고시 본문은 이번에 못 읽었다. 확인 필요.
- 안전한 길: 홈택스나 세무서에서 개인사업자 등록(업종은 게임 소프트웨어 개발 및 공급 등, 1일 내외), 그 뒤 정부24 에서 통신판매업 신고, 번호를 Play Console 에 넣는다. 처음 매출은 작아도 반복해서 파는 것이라 사업자등록을 먼저 해 두는 편이 정산과 세금 정리에 편하다.
- 구글 정산금과 AdMob 수익은 소득세(사업소득, 다음 해 5월 종합소득세) 대상이라는 것이 기본 원칙이다. 부가세와 해외 지급분 처리는 세무사나 홈택스에 한 번 묻는다. 확인 필요.

## 5단계. 내부 테스트, 그리고 바로 비공개 테스트

- 앱 만들기 뒤 테스트 및 출시, 내부 테스트에 첫 AAB 를 올려 내 폰에서 설치, 광고(테스트 광고), 결제(라이선스 테스터)를 확인한다. 내부 테스트만이면 데이터 보안 양식이 면제된다.
- 같은 AAB 를 비공개 테스트 트랙에 올린다. 2023-11-13 이후 만든 개인 계정은 테스터 12명 이상이 14일 연속 옵트인해야 프로덕션을 신청할 수 있다. 이탈에 대비해 15명에서 20명을 모은다(구글 그룹으로 이메일 목록을 만들면 편하다). 중간에 나갔다 다시 들어오면 그 사람의 14일은 다시 센다. 도움말은 이 요건을 개인 계정에만 걸고 조직 계정은 말하지 않는다. 같은 계정의 두 번째 앱에도 다시 필요한지는 문서에 없다(그때 프로덕션 신청 화면에서 확인).
- 테스터가 실제로 몇 번 열고 의견을 주게 한다. 참여가 부족하면 비공개 테스트를 더 하라는 답이 올 수 있다.
- 업로드마다 사전 출시 보고서(자동 기기 테스트)의 충돌과 경고를 본다.
- 출처: support.google.com/googleplay/android-developer/answer/14151465, answer/7159011

## 6단계. 스토어 등록정보

- 앱 아이콘: 512x512, 32비트 PNG(알파), 1024 KB 이하. `store/icon-512.png` 를 쓴다.
- 피처 그래픽: 1024x500, JPEG 또는 24비트 PNG(알파 없음). 새로 만들어야 한다.
- 휴대전화 스크린샷: 2장 이상 8장 이하, JPEG 또는 24비트 PNG, 각 변 320에서 3840px, 긴 변이 짧은 변의 2배 이하. 세로 1080x1920 이상으로 4장 이상이면 추천 노출 조건에 맞는다. 실제 게임 화면으로 찍는다.
- 짧은 설명 80자, 자세한 설명. 아동을 부르는 표현은 피한다(타깃층 판단에 영향).
- 확률형 요소(보석으로 여는 상자)가 있다는 것을 설명에 짧게 적어 두면 안전하다(필수 여부 확인 필요).
- 출처: support.google.com/googleplay/android-developer/answer/9866151

## 7단계. 앱 콘텐츠 설문(정책, 앱 콘텐츠)

- 개인정보 처리방침: 한국어로 쓰고 공개 주소에 올린다. 수집 항목(광고 ID, 대략적 위치, 구매 내역, RevenueCat 익명 사용자 ID, 충돌과 진단 정보), 목적, 제3자(Google AdMob, RevenueCat), 보관 기간, 이용자 권리, 14세 미만 관련 문구, 문의처. 같은 주소를 `.env.store` 의 `VITE_PRIVACY_URL` 에도 넣는다(약관 `VITE_TERMS_URL`, 문의 `VITE_SUPPORT_URL` 도).
- 데이터 보안: 비공개 테스트부터 필수. AdMob 과 RevenueCat 의 공식 데이터 공개 문서를 보고 기기 또는 기타 ID, 구매 내역, 앱 상호작용, 진단을 해당하는 대로 체크. 게임 코드 자체는 소리 파일 읽기 말고는 네트워크로 아무것도 보내지 않는다(분석 이벤트는 기기 안에만 쌓인다).
- 콘텐츠 등급(IARC): 카테고리는 게임. 만화 폭력, 확률형 아이템 구매 있음, 광고 있음, 사용자 생성 콘텐츠 없음으로 정직하게 답한다. 한국은 GRAC 등급(전체, 12, 15, 청소년이용불가)이 IARC 로 매겨진다. 구글 플레이에만 내는 동안 별도 GRAC 신청이 필요한지는 확인 필요(저장소 조사 문서 `docs/research/02_수익화_유통_분석.md` 는 필요 없다고 읽힌다).
- 타깃층과 콘텐츠: "먼저 정할 것" 4번대로. 아동을 넣지 않으면 AdMob 의 아동 대상 처리 태그도 끈 채로 일관되게 둔다.
- 광고: 포함(보상형). 앱 액세스: 로그인 없이 모든 기능 사용 가능. 정부, 금융, 건강, 뉴스 앱 아님.
- 광고 ID 선언: 광고 SDK 를 쓰므로 사용한다고 선언.
- 출처: support.google.com/googleplay/android-developer/answer/10787469, answer/9859455, answer/9893335

- 상품 11종(`src/meta/data/catalog.ts`, `docs/명세_메타.md`): baby_cat_pack, starter_pack, growth_pack, butler_pass, season_pass, gem_pass, piggy_bank, gems_260, gems_680, gems_1450, gems_4600. 코드의 ID 와 똑같이 만든다. ID 는 영구다.

- RevenueCat: 앱 등록, Google Play 서비스 계정 자격증명 연결, 평생 상품(butler_pass 등)은 non-consumable 로 지정. 30일짜리 패스는 구글 쪽에서 다시 살 수 있는 소비형이 되므로 게임의 "다시 사면 30일 연장" 이 맞게 도는지 테스트 결제로 본다.

- Play Billing Library: 지금(2026-11) 신규 앱과 업데이트는 버전 8 이상이어야 한다(버전 7은 2026-08-31 마감, 연장 2026-11-01 도 지남. 버전 8은 2027-08-31 까지). `@revenuecat/purchases-capacitor` 14.0.0 부터 Billing Library 9.1.0 을 쓰므로 14.x 를 설치한다(14.1.0 의 빌링 버전은 노트에 없어 업로드 때 Play Console 경고로 확인). 출처: developer.android.com/google/play/billing/deprecation-faq, github.com/RevenueCat/purchases-capacitor/releases
- 환불: 지금 Capacitor 어댑터는 환불을 감지하지 못한다(`docs/handoff/platform.md` 알려진 공백). 첫 출시는 이대로 가되 매출을 보고 다시 판단한다.

## 9단계. 광고(AdMob)

- AdMob 계정을 만들고 앱 추가(아직 게시 안 됨으로 등록 가능), 보상형 광고 단위 1개(어댑터는 ID 하나를 쓴다).
- 개발과 테스트 중에는 테스트 광고만 쓴다(`VITE_ADMOB_TESTING=1` 또는 구글 테스트 ID). 내 폰에서 실제 광고를 누르면 무효 트래픽으로 계정이 정지될 수 있다.
- 출시 빌드에서만 실제 ID 를 넣고 테스트 모드를 끈다.
- app-ads.txt: 개발자 웹사이트의 루트(`https://도메인/app-ads.txt`)에 AdMob 이 주는 한 줄을 둔다. GitHub 프로젝트 페이지(`kymmmm01.github.io/Project1/`)는 루트가 아니므로 사용자 페이지 저장소(`이름.github.io`)나 도메인을 쓴다. 개인정보 처리방침도 같은 곳에 올리면 편하다. Play 등록정보의 웹사이트 칸에 같은 도메인을 넣는다.
- UMP(EEA, 영국 동의): 그 나라에 낸다면 필수. 한국 우선 출시면 국가 설정에서 빼고 다음 업데이트로 미룬다.
- 출처: support.google.com/admob/answer/9363762, developers.google.com/admob/android/privacy

## 10단계. 확률 공개(구글 정책과 게임산업법)

- 구글: 돈으로 무작위 아이템을 얻는 구조는 구매 전에, 구매와 가까운 곳에서 확률을 분명히 보여 줘야 한다(answer/9858738). 지금 상자 구매 확인 단계의 확률표가 이에 해당한다. 보석을 사는 화면에도 확률 안내로 가는 길을 두면 더 안전하다.
- 한국 게임산업진흥법(제33조 제2항, 시행령 제19조의2, 별표 3의2, 2024-03-22 시행): 돈으로 직접이나 간접으로 사는 아이템 중 결과가 우연으로 정해지는 것(캡슐형, 강화형, 합성형)이 대상이다. 무료 재화로 사도 그 재화를 유료로도 살 수 있으면 대상이다(보석으로 여는 상자가 여기에 든다).
  - 공개할 것: 나올 수 있는 모든 아이템의 종류, 등급별 확률, 한정 판매면 수량이나 기간, 천장이 있으면 확정 조건, 확률이 바뀌면 바뀐 내용(미리 게시).
  - 공개할 곳: 게임 안의 구매, 조회 또는 사용 화면, 그리고 홈페이지(문자나 숫자로 검색되는 형태). 광고물에는 "확률형 아이템 포함" 문구.
  - 예외: 제작, 배급, 제공하는 자가 모두 최근 3년 연평균 매출 1억 원 이하인 중소기업이면 의무에서 빠진다는 해설이 많다(시행령 원문은 이번에 못 읽음). 매출이 커지면 바로 의무가 생기고, 공개한 확률이 틀리면 예외와 상관없이 문제가 된다.
  - 제재: 시정권고와 시정명령, 명령을 안 따르면 2년 이하 징역 또는 2천만 원 이하 벌금. 2025-08-01 부터는 표시 위반 손해배상에서 게임사가 과실 없음을 입증해야 하고, 고의면 손해액의 3배까지 배상.
  - 할 일: 예외에 기대지 말고 지금처럼 게임 안 구매 확인 단계에 공개한다. 개인정보 처리방침을 올리는 웹사이트에 확률표 페이지도 같이 올려 두면 홈페이지 조건까지 채운다(`OddsTable` 이 원본이라 같은 숫자로 만든다).
  - 출처: law.go.kr 의 게임산업진흥법 시행령 별표 3의2, korea.kr/news/policyNewsView.do?newsId=148926013, lawtimes.co.kr/news/articleView.html?idxno=210245(2025-08-05). 확정은 별표 원문과 문체부 해설서(grac.or.kr)로 한 번 더.
