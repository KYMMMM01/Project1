# 프로필 꾸미기 설계서

상태: 설계 확정(2026-11-25, 13장의 권장안을 사용자가 모두 확정). 코드는 아직 바꾸지 않았다.

## 0. 사용자 지시(2026-11-24)

- 홈 상단의 레벨 동그라미에는 유저 프로필 그림을 넣는다. 개인 사진이 아니라 게임이 준비한 그림 중에서 고른다. 레벨은 동그라미 아래에 보인다.
- 경험치 바 자리에는 닉네임이 나오고, 이 닉네임 바(이름표)를 꾸밀 수 있다.
- 다른 유저가 꾸민 모습도 볼 수 있다.
- 테두리 같은 꾸미기는 상점의 꾸미기 탭에서 팔거나 랭킹, 업적 보상으로 준다.
- 업적으로 주는 꾸미기는 대부분 "업적을 달성하면 상점에서 골드로 살 수 있게 열리는" 방식이고, 달성하기 힘든 명예 업적 몇 개만 바로 준다.
- 랭킹 보상은 모두 시즌이 끝나면 바로 지급한다.
- 아이콘 그림은 고양이 20종 그림에 새로 그린 컷 여러 개를 더한다.
- 레퍼런스(다른 게임의 이름표 꾸미기, 테두리, 아이콘 화면)는 구조만 참고한다. 그림과 화면은 우리 화풍(종이 질감, 고양이)으로 새로 만든다.

## 1. 한눈에 보기

꾸미기는 세 종류다.

| 종류 | 보이는 곳 | 저장 이름 |
|---|---|---|
| 아이콘 | 동그라미 안 | `icon` |
| 테두리 | 동그라미 둘레 | `frame` |
| 이름표 | 닉네임 뒤 배경 | `plate` |

얻는 길은 여섯 가지다.

| 얻는 길 | 무엇 | 지급 방식 |
|---|---|---|
| 기본 | 아이콘 1(솜방망이), 테두리 1, 이름표 1 | 처음부터 가짐 |
| 고양이 | 고양이 20종 아이콘 | 기본 16종은 처음부터, 수호신 4종은 판에서 처음 각성시키면(4.3) |
| 상점 상시 판매 | 골드 또는 보석 | 상점 꾸미기 블록에서 구매 |
| 업적 해금 | 업적 14개에 하나씩 | 그 업적 보상을 받으면 상점에 골드 가격으로 열림 |
| 명예 업적 | 업적 5개에 하나씩 | 업적 보상을 받을 때 보석과 함께 바로 지급 |
| 주간 랭킹 | 순위 구간별 | 주간 랭킹이 끝나면 서버가 확정하고, 앱이 켜지면 바로 지급 |

기존 꾸미기 체계(러그, 소환 이펙트)를 그대로 넓혀 쓴다. 상점에는 이미 "꾸미기" 블록이 있고, 보상 묶음(`Bundle.cosmetics`)과 중복 시 보석 100 환산(`DUPLICATE_COSMETIC_GEMS`)도 있다.

## 2. 홈 상단

### 2.1 지금

`src/screens/shell/HomeTopBar.ts`, `LevelBadge.ts`, `layoutMath.ts`.

- 화면 폭 720(`DESIGN_W`). 첫 줄 높이 92(`TOP_ROW_H`), 둘째 줄은 재화 알약.
- 첫 줄 왼쪽부터 레벨 배지 칸 112(`BADGE_SLOT`, `BADGE_R = 50`), 경험치 바 폭 352(`XP_BAR_W`) 높이 40, 도감 버튼 칸 88, 설정 버튼 칸 88.
- 레벨 배지는 종이 원 안에 "Lv"와 숫자, 바깥 고리가 경험치를 채운다. 바에도 같은 경험치가 `48 / 120` 꼴로 나온다. 둘 다 레벨업 연출을 따로 갖고 있다.
- 배지와 바는 눌러도 아무 일이 없다.

### 2.2 바꾼 뒤

```
[테두리+아이콘]  [ 이름표: 닉네임              ]  [도감] [설정]
[  Lv 12 띠   ]  [ 얇은 경험치 줄               ]
```

- **동그라미**: 아이콘 지름 80, 테두리 그림은 아이콘 지름의 1.3배(약 104) 상자 안에 그린다. 배지 칸 112 안에 들어간다.
- **레벨 띠**: 아이콘(지름 80) 아래 가장자리에 겹쳐 붙는 작은 종이 띠. "Lv 12"를 한 줄로 쓴다(`shell.lv` 재사용). 첫 줄 가운데를 `rowA`라 하면 아이콘 아래 끝이 `rowA + 40`이고, 재화 알약의 위 끝이 `rowA + 54`(`rowB = rowA + 94`, 알약이 위로 `H/2 + 4` 튀어나옴)라서, 띠는 높이 14 안팎으로 아랫변이 `rowA + 54`를 넘지 않게 둔다. 첫 알약이 x 45부터 시작해 배지 칸과 가로로 겹치기 때문이다. 띠 글자는 24px(`MIN_FONT`)이 들어가도록 띠 그림이 글자보다 작아 보이지 않게 그린다.
- **이름표**: 지금 바 자리(폭 352). 높이 약 60. 이름표 그림 위 가운데에 닉네임. 닉네임은 2자에서 12자(`NAME_MIN`, `NAME_MAX`)다. 한글 12자는 24px에서 약 288이라 글자 칸을 폭 300으로 잡고(이름표 그림의 글자 칸 규칙, 9장), 그래도 넘치면 `fitLabel`로 24px 아래로 줄이지 않고 끝을 말줄임한다. `fitWidth`는 하한 없이 줄여 글자 하한 규칙을 어기므로 쓰지 않는다.
- **경험치**: 바를 이름표에 내주므로 이름표 아래에 높이 약 10의 얇은 경험치 줄을 남긴다. 숫자는 안 쓴다. 레벨업 연출은 이 줄 하나만 맡고, 배지의 경험치 고리는 없앤다. 그러면 지금 둘로 나뉜 레벨업 연출이 하나로 줄어든다.
- 이름표 60과 간격 6과 경험치 줄 10을 합쳐 76이라 첫 줄 높이 92 안에 들어간다. 첫 줄 높이를 바꾸지 않으므로 모든 홈 탭의 콘텐츠 높이(`TOP_BAR_CONTENT_H = 196`)도 그대로다.
- 테두리 상자 104는 `rowA - 52`에서 `rowA + 52`까지라, 위로는 패딩 8 안에서 6이 남고 아래로는 알약 위 끝까지 2가 남는다. 테두리 그림은 이 상자를 넘지 않게 그리고(9장), 실제 화면 사진으로 노치, 알약과 겹치지 않는지 확인한다.
- **누르면**: 동그라미나 이름표를 누르면 "프로필 꾸미기" 화면(3장)이 열린다.
- **잠금**: 프로필 꾸미기 화면과 고양이 아이콘 바꾸기는 처음부터 쓸 수 있다. 상점 꾸미기 블록과 구매는 지금처럼 꾸미기 기능 잠금(3판, `schedule.ts`의 `cosmetics: { runs: 3 }`)을 따른다. 잠긴 동안에는 꾸미기 화면의 "상점에서 보기" 버튼을 숨기고, 얻는 방법에 "판을 3번 하면 상점이 열려요"를 쓴다. 기능 안내 문구("러그와 소환 이펙트로 꾸며요", `src/screens/system/strings.ts`)도 아이콘, 테두리, 이름표를 포함하게 고친다.

### 2.3 로그인하지 않았을 때

닉네임은 서버(`users/{uid}.name`)에만 있고, 로그인해야 생긴다(`ranking.myName()`이 로그인 전에는 null).

- 이름표에는 "이름 없는 집사"를 쓴다. 이 문구는 소스에 들어가므로 글꼴 서브셋에 자동으로 들어간다.
- 아이콘, 테두리, 이름표는 로그인 없이도 고르고 쓸 수 있다(기기 저장). 다른 유저에게 보이는 것만 로그인이 필요하다.
- 로그인하면 서버 닉네임을 이름표에 쓴다. 홈은 켤 때와 이름을 바꾼 뒤에 이름을 다시 읽는다. 오프라인이면 마지막으로 읽은 이름을 기기 설정에 기억해 둔 것을 쓴다.

## 3. 프로필 꾸미기 화면

동그라미나 이름표를 누르면 뜨는 전체 화면. 랭킹 화면처럼 `ScreenScaffold`(스크롤)로 연다. 팝업(`Popup`)은 내용이 화면보다 크면 통째로 줄여 24px 글자 하한이 깨지고, 팝업 안에 `ScrollView`를 넣은 선례도 없어서 쓰지 않는다. 미리보기는 스크롤 위에 고정한다.

- **위쪽 미리보기**: 지금 고른 아이콘, 테두리, 레벨 띠, 이름표와 내 닉네임을 홈과 같은 모양으로 크게 보여 준다. 고른 항목의 이름과 얻는 방법 한 줄("상점에서 골드 8,000", "'불패의 집사' 업적 보상", "주간 랭킹 1위 보상")을 그 옆에 쓴다.
- **탭**: 아이콘, 테두리, 이름표(`SegmentTabs`).
- **목록**: 아이콘과 테두리는 4열(칸 폭 약 150), 이름표는 2열 격자. 칸 안에는 그림만 두고 이름은 미리보기 옆에만 쓴다(4열 칸에 24px 이름을 넣으면 잘리므로). 가진 것은 또렷하게, 아직 없는 것은 어둡게 하고 자물쇠를 얹는다. 없는 것을 눌러도 미리보기에는 보여 주고, 얻는 방법을 알려 준다. 상점에서 살 수 있는 것이면 "상점에서 보기" 버튼이 상점 꾸미기 블록으로 데려간다(`openShopSection('cosmetics')`).
- **정렬**: 장착 중, 가진 것, 살 수 있는 것, 잠긴 것 순. "가진 것만" 토글을 둔다.
- **적용**: 세 탭에서 고른 것을 한 번에 적용한다. 기기 저장에 바로 쓰고, 로그인 상태면 서버에도 올린다(5.2).
- **닉네임 바꾸기**: 로그인 상태면 화면 아래에 기존 `changeNameFlow`를 여는 버튼을 둔다. 지금 설정 화면에 있는 같은 버튼은 그대로 둔다.

## 4. 데이터

### 4.1 저장(ProfileData)

지금 `cosmetics: { owned: string[]; rug: string; fx: string }`(`src/meta/types.ts`)이다. 장착 함수 `equip(id)`가 `c[def.kind] = id`로 쓰므로, 새 종류 이름이 곧 저장 필드 이름이 된다.

```ts
cosmetics: {
  owned: string[];   // 기존: 산 것, 보상으로 받은 것(고양이 아이콘은 넣지 않는다, 4.3)
  rug: string;
  fx: string;
  icon: string;      // 새: 기본 'icon_w_paw'
  frame: string;     // 새: 기본 'frame_default'
  plate: string;     // 새: 기본 'plate_default'
}
rankClaimed: string[]; // 새: 받은 주간 랭킹 보상 '<uid>:<주 id>'('ab12:week-2026-11-23'), 최근 52개
mythicMet: string[];   // 새: 판에서 각성시켜 본 수호신 id(4.3)
```

- `defaultProfile`에 기본값을 넣고, `owned` 기본값에 `frame_default`, `plate_default`를 더한다. 기본 아이콘은 고양이 아이콘이라 `owned`에 넣지 않는다.
- `deepFill`(`src/core/save.ts`)은 객체의 새 키(`icon`, `frame`, `plate`, `rankClaimed`, `mythicMet`)는 채우지만 배열은 저장값을 통째로 쓴다. 그래서 기존 유저의 `owned`에는 `frame_default`, `plate_default`가 들어가지 않는다. `normalizeProfile`이 지금 `rug_default`, `fx_default`를 밀어 넣는 것처럼 두 기본값도 `owned`에 밀어 넣는다.
- `normalizeProfile`의 장착값 검사는 지금 `owned.includes`(러그, 이펙트)다. 새 종류는 아래 `owns(id)`로 검사하고, 쓸 수 없으면 기본값으로 되돌린다.
- `owned`에서 모르는 id를 지우지 않는다. 문자열인지와 중복만 정리한다. 옛 앱이 클라우드 사본을 받아 정리한 뒤 다시 올리면(`readCloud`, `adoptCloud`, `write`) 새 앱에서 산 아이템이 지워지기 때문이다. 장착값만 모르는 id면 기본값으로 그린다.
- `rankClaimed`는 형식이 맞는 값만, 최근 52개만 남긴다. 계정 id를 앞에 붙이는 이유는 한 기기에서 구글 계정을 바꿔 같은 기기 저장을 쓸 때, 한 계정이 받은 주 때문에 다른 계정의 보상이 건너뛰어지지 않게 하려는 것이다.
- 필드만 더하면 `deepFill`이 기존 저장에 기본값을 채워 주므로 저장 이전 단계는 필요 없다. 그래서 `PROFILE_VERSION`은 2로 둔다. 버전을 올리면 옛 앱이 새 냥이 코드를 거절하고, 이전 단계도 필요 없으므로 올릴 이유가 없다.
- 냥이 코드 왕복 테스트(`tests/meta.profile.test.ts` 577줄)의 키 목록에 `rankClaimed`, `mythicMet`를 더한다.
- 클라우드 저장은 필드 병합이 아니라 한쪽 사본을 통째로 고른다. 그래서 꾸미기 소유와 `rankClaimed`도 고른 쪽 것이 남는다. 랭킹 보상은 서버에 지급 기록이 남아 있어서, 옛 사본을 골라 잃어도 다음에 켤 때 다시 받는다(5.3).

### 4.2 카탈로그(`src/meta/data/catalog.ts`)

```ts
type CosmeticKind = 'rug' | 'fx' | 'icon' | 'frame' | 'plate';
type CosmeticSource =
  | { type: 'default' }
  | { type: 'chapter'; chapter: number }        // 기존
  | { type: 'gems'; price: number }             // 기존
  | { type: 'reward' }                          // 기존: 패스, 현금 상품
  | { type: 'gold'; price: number }             // 새: 상점 상시 골드 판매
  | { type: 'achievement'; key: string; price: number } // 새: 업적을 받으면 골드로 살 수 있음
  | { type: 'honor'; key: string }              // 새: 명예 업적 보상으로 바로 지급
  | { type: 'rank'; tier: RankTier }            // 새: 주간 랭킹 보상
  | { type: 'unit'; unit: string };             // 새: 고양이 아이콘
```

- 업적 해금 상태는 저장하지 않고 계산한다. `achv.claimed`에 그 업적 키가 있으면 열린 것이다. `claimed`는 한 번 들어가면 빠지지 않으므로 해금도 되돌아가지 않는다. 이미 업적을 받은 기존 유저는 업데이트하자마자 해당 꾸미기가 열려 있다.
- 명예 업적은 `AchievementDef`에 `cosmetic?: string`을 더하고, `takeAchievement`가 만드는 보상을 `{ gems: def.gems, cosmetics: [def.cosmetic] }`로 바꾼다. 보석 값은 그대로라 보석 합계 1,115와 이를 고정한 테스트는 바뀌지 않는다. 미션 탭 업적 줄(`AchievementRowView.ts`의 `partsOf`)이 꾸미기 보상 칩도 그리게 한다.
- **소유 판정 함수 `owns(id)`**: 하나를 두고 `cosmetics()` 행의 소유 표시, `equip`, `buyCosmetic`의 이미 가짐 검사, `normalizeProfile`의 장착 검사가 모두 이것을 쓴다. 지금은 이 네 곳이 각자 `owned.includes`를 쓰고, `equip`은 `owned`에 없으면 `not_owned`로 거절한다. 그대로 두면 `owned`에 없는 고양이 아이콘은 장착도 안 되고, 다음 로드 때 기본값으로 돌아간다. `owns`는 출처가 `unit`이면 4.3의 판정을, 나머지는 `owned`를 본다.
- 장착 판정(`CosmeticRow.equipped`, 지금은 `c.rug === def.id || c.fx === def.id`)은 `c[def.kind] === def.id`로 바꾼다. `profile.equipped` getter는 `{ rug, fx }` 그대로 두어 게임 화면(`app/flow.ts`)을 건드리지 않고, 프로필 쪽은 새 getter `profile.look`(`{ icon, frame, plate }`)을 쓴다.

### 4.3 고양이 아이콘

- 고양이 아이콘은 `owned`에 넣지 않고 계산한다. 지금 코드에 "고양이를 얻었다"는 기준은 없다. 기본 고양이 16종(`BASE_UNITS`)은 새 프로필부터 모두 레벨 1로 들어 있어서 처음부터 다 가진 상태다. 그래서 이 16종 아이콘은 처음부터 쓸 수 있다.
- 수호신 4종(`w_tiger`, `r_star`, `m_cosmo`, `t_lucky`)은 판 안에서 각성으로만 나오고 자기 레벨이나 카드가 없다. 지금 저장에는 수호신을 한 번이라도 만들었는지(`achv.mythic`, 참 거짓 하나)만 있고 어느 수호신인지는 없다. 그래서 `mythicMet`를 새로 두고, 판이 끝날 때 그 판에서 각성시킨 수호신 id를 넣는다. 그 수호신의 아이콘이 열린다.
- 업데이트 전에 이미 `achv.mythic`가 참인 유저는 어느 수호신이었는지 알 수 없으므로, 4종을 모두 연다.
- 시작 고양이 솜방망이(`w_paw`) 아이콘이 기본값이다.

`buyCosmetic(id)`(`src/meta/economy.ts`)를 넓힌다.

### 4.5 환불

환불 회수(`profile.ts` 524줄 근처)는 지금 러그만 기본값으로 되돌린다. 처음 판에서는 아이콘, 테두리, 이름표를 현금 상품 묶음에 넣지 않는다. 다만 나중에 넣을 수 있으므로(사용자, 2026-11-25), 1단계에서 이 회수를 종류 구분 없이 "회수한 아이템을 끼고 있으면 그 종류의 기본값으로" 되돌리게 바꿔 둔다. 그러면 현금 상품에 꾸미기를 더할 때는 카탈로그 묶음과 Play 인앱 상품 등록만 하면 된다.

## 5. 서버

### 5.1 지금 있는 것

- `setName`(`functions/src/index.ts`): 이름을 검사(`cleanName`)한 뒤 `users/{uid}.name`, 이번 주와 무한 보드의 내 기록, 두 접힌 보드 문서의 상위 100 행 안 내 이름을 한 트랜잭션으로 고친다. 쿨다운 30초.
- 접힌 보드 문서 `boards/endless`, `boards/week`: `top: [{uid, name, score}] x 100`. 누구나 읽는다. `refreshBoards`가 10분마다 덮어쓴다.
- 지난 주의 `boards/week-YYYY-MM-DD/entries/*`는 지우지 않아 남아 있다. 주는 서울 월요일 0시에 바뀐다.
- `firestore.rules`의 `users/{uid}`는 키를 `['v','device','savedAt','data','bestWave','name','updatedAt']`로 제한하고, `name`은 클라이언트가 못 바꾼다. 나머지 컬렉션은 모두 막혀 있다.

### 5.2 착용 정보 올리기: `setLook`

다른 유저에게 보이려면 서버가 그 사람의 착용 정보를 알아야 한다.

- 새 onCall `setLook({ icon, frame, plate, level })`. 로그인 필수.
- 검사: 세 id가 서버도 아는 카탈로그 id인지, 종류가 맞는지 본다. 카탈로그 id 목록은 `functions/src/rules.ts`처럼 firebase를 import하지 않는 파일(`functions/src/looks.ts`)에 두고, 게임과 서버가 같이 import한다. 테스트로 게임 카탈로그와 서버 목록이 같은지 확인한다. `level`은 1에서 99 정수만 받는다.
- 소유 검사: 기기 저장은 클라이언트 것이라 서버는 상점에서 산 것인지 확인할 수 없다. 그래서 소유는 랭킹 보상만 확인한다(`grants/{uid}`에 그 아이템이 있어야 함, 5.3). 나머지는 카탈로그 id인지만 본다. 꾸미기라 조작해도 남에게 주는 피해가 작다.
- 쓰는 곳: `setName`과 같은 자리. `users/{uid}.look`, 이번 주와 무한 보드의 내 기록 문서, 두 접힌 문서의 내 행. `submitRun`이 새 기록을 쓸 때와 `refreshBoards`가 상위 100을 다시 만들 때도 `look`을 같이 복사한다.
- 쿨다운 30초(`rate/{uid}.lookAt`). 앱은 "적용"을 누를 때와 레벨이 오를 때 올린다. 로그인 직후 기기 착용과 서버 착용이 다르면 한 번 올린다.
- 재시도: 올릴 것이 생기면 앱은 메모리에 "올릴 것 있음"을 표시한다. 쿨다운(`too-soon`)이나 네트워크 실패로 거절되면 표시를 남겨 두고, 다음에 앞으로 올 때나 다음 레벨 변화 때 최신 값으로 다시 올린다. 그래서 적용 직후 30초 안에 레벨이 올라도 레벨이 빠지지 않는다.
- `firestore.rules`: `users` 허용 키에 `look`을 더하고, `name`처럼 클라이언트가 바꿀 수 없게 한다(새 문서에는 금지, 기존 문서는 값이 같아야 함).
- **배포 순서**: 규칙을 먼저, 함수를 나중에 배포한다. 클라우드 저장은 `users/{uid}`에 병합 쓰기(`setDoc` merge)를 하고 규칙의 허용 키 검사는 병합된 결과 문서를 본다. 지금 규칙이 남은 채 서버가 `look`을 먼저 쓰면, 그 순간부터 그 유저의 클라우드 저장이 모두 거절된다.
- 모르는 id를 받은 옛 앱은 그 칸을 기본값으로 그린다. 새 아이템을 추가해도 옛 앱이 깨지지 않는다.

`look`의 모양: `{ i: string, f: string, p: string, lv: number }`. 접힌 문서 상위 100 행마다 약 60바이트가 늘어 문서 크기(1MiB 한도)에 여유가 크다.

### 5.3 주간 랭킹 보상: `settleWeek`와 `claimGrants`

"랭킹 시즌"은 지금 서버에 있는 주간 랭킹(서울 월요일 0시 시작, 7일)으로 정한다. 무한 보드는 기간이 없어 보상을 주지 않는다. 패스 시즌(30일)은 기기 날짜 기준이라 서버와 어긋날 수 있어 쓰지 않는다.

**확정(서버)**
- 새 스케줄 함수 `settleWeek`: 한 시간마다(`every 1 hours`, Asia/Seoul) 돈다. 할 일이 없으면 바로 끝난다. 주 1회로만 돌리면 한 번 실패했을 때 다음 실행이 7일 뒤라 "끝나면 바로 지급"이 깨지기 때문이다. 보통은 월요일 0시와 1시 사이에 확정된다.
- 확정할 주: 지난주 id는 `seoulWeekKey(지금 - 7일)`로 구한다. `meta/weekSettle.last`가 비어 있으면(첫 배포) 지난주 하나만 확정한다. `last`와 지난주 사이에 빠진 주가 있으면(장애나 배포 공백) 오래된 주부터 차례로 확정한다.
- 지난 주 보드 `boards/week-<지난주>/entries`를 점수 높은 순, 같은 점수면 먼저 낸 순(`orderBy('score','desc').orderBy('at','asc')`, 지금 상위 100과 같은 색인)으로 100명 읽는다.
- 순위 구간에 따라 `grants/{uid}` 문서의 `weeks` 맵에 `{ [weekId]: { rank, items } }`를 더한다.
- 멱등: 한 주의 지급을 모두 쓴 뒤에 `meta/weekSettle.last`를 그 주로 옮긴다. 실패하면 커서를 옮기지 않아 한 시간 뒤 실행이 다시 한다. 다시 쓰더라도 `grants/{uid}.weeks[주 id]`를 같은 값으로 덮어쓰므로 두 번 지급되지 않는다. 환불 감지 함수 `pollVoidedPurchases`의 커서 방식과 같다.
- 동점 처리: 위 정렬로 매긴 자리 순서를 그대로 순위로 쓴다(같은 점수면 먼저 기록한 사람이 위). `myRank`는 동점을 같은 순위로 세므로 화면 순위와 보상 순위가 다를 수 있다. 보상 순위는 확정 때 `grants`에 적은 값을 보여 준다.
- `onUserDeleted`에 `grants/{uid}` 삭제를 더한다. 접힌 보드 문서의 상위 100 행(이름, `look`)은 다음 `refreshBoards`까지 최대 10분 남는다. 지금 이름도 같으므로 받아들인다.

**받기(앱)**
- 새 onCall `claimGrants()`. 로그인 필수. `grants/{uid}.weeks`에서 최근 52주를 돌려준다(`rankClaimed` 보관 개수와 같다). 서버는 받음 표시를 하지 않는다. 52주보다 오래 앱을 켜지 않은 유저의 보상은 사라진다.
- 앱은 켤 때, 다시 앞으로 올 때, 랭킹 화면을 열 때 부른다(8초 타임아웃, 실패하면 조용히 다음에). 돌려받은 주 중 `rankClaimed`에 `<uid>:<주 id>`가 없는 주를 지급하고(`applyBundle`, 이유 `rank_reward`), 그 값을 `rankClaimed`에 넣고 저장한다. 보상 팝업(`showRewards`) 제목은 "지난주 주간 랭킹 12위"다.
- 그래서 "시즌이 끝나면 바로 지급"은 이렇게 동작한다: 월요일 0시에서 1시 사이에 서버가 확정하고, 그 뒤 앱을 켜거나 다시 열면 그 자리에서 받는다. 게임을 켜 둔 채 월요일을 넘기면 다음에 앞으로 올 때 받는다. 서버가 기기 저장에 직접 쓸 수는 없어서(저장은 기기가 통째로 가진다) 앱이 한 번은 켜져야 한다.
- 옛 클라우드 사본을 골라 `rankClaimed`와 아이템을 잃어도, 서버 기록이 남아 있어 다시 받는다. 이미 가진 아이템이면 기존 규칙대로 보석 100으로 바뀐다.

**구간과 보상(초안)**

| 구간 | 테두리 | 이름표 | 아이콘 |
|---|---|---|---|
| 1위 | `frame_rank_1` 왕관 | `plate_rank_1` | `icon_rank_1` 트로피 냥이 |
| 2~3위 | `frame_rank_3` 금 리본 | | |
| 4~10위 | `frame_rank_10` 은 리본 | `plate_rank_10` | |
| 11~100위 | `frame_rank_100` 종이 메달 | | |

- 같은 구간을 다시 하면 이미 가진 아이템이라 보석 100이 된다. 1위를 여러 번 한 사람에게는 보석만 쌓인다.
- 상위 구간을 받으면 아래 구간 아이템은 주지 않는다.

## 6. 랭킹 화면에서 다른 유저 보기

`src/screens/system/rankingScreen.ts`, `src/platform/ranking.ts`.

- 지금 한 줄은 높이 76에 순위(x=SIDE+34), 이름(x=SIDE+86부터), 점수(오른쪽)이고, 눌러도 아무 일이 없다.
- 순위와 이름 사이에 테두리 상자 56(그 안의 아이콘 지름 약 43)을 넣는다. 아이콘을 56으로 하면 테두리가 약 73이 되어 줄 높이 76에 닿고 세 자리 순위("100")와도 겹치므로, 56은 테두리 상자 기준이다.
- 이름 시작을 64만큼 오른쪽으로 밀고, 이름 최대폭 식(`w - SIDE*2 - 110 - 점수폭 - 24`)의 110도 174로 같이 올린다. 시작만 밀면 이름 끝이 점수 쪽으로 16 파고든다. 이 줄 함수는 내 기록 줄에도 같이 쓰인다.
- 이름표 배경은 줄에 깔지 않는다(100줄이 시끄러워지고 그림 100장을 그려야 해서).
- 줄을 누르면 프로필 카드 팝업: 큰 아이콘과 테두리, 레벨 띠, 이름표와 이름, 그리고 지금 보고 있는 보드의 기록(웨이브)과 순위. 접힌 문서 행은 그 보드의 점수만 갖고 있어서, 다른 보드의 기록까지 보여 주려면 읽기가 더 든다. 처음 판은 지금 보드 것만 보여 준다.
- 내 기록 줄도 같은 모양으로 그린다. 내 줄은 접힌 상위 100 문서가 아니라 `myRank` 응답(내 기록 문서)에서 오고 100위 밖이면 접힌 문서에 없다. 그래서 내 줄은 서버 값 대신 기기의 지금 착용(`profile.look`)과 레벨로 그린다.
- `BoardRow`를 `{ uid, name, score, look? }`로 넓히고, `rows()` 파서가 `look`을 읽는다. 없거나 모르는 id면 기본값으로 그린다.
- 다른 유저의 꾸미기를 볼 수 있는 곳은 처음 판에서는 랭킹 상위 100(전체, 주간)뿐이다. 100위 밖 유저는 볼 수 없다.
- 다른 유저의 이름 속 한글이 게임 글꼴 서브셋에 없으면 시스템 글꼴로 그려진다. 지금도 있는 문제이고 이 기능에서 새로 생기지 않는다.

## 7. 상점

- 새 탭을 만들지 않는다. 상점 탭이 6개에서 7개가 되면 칸이 114에서 약 98로 좁아져 글자가 작아진다. 대신 기존 꾸미기 블록(`cosmeticsBlock`) 안에 소제목(`PaperLabel`)으로 "아이콘", "테두리", "이름표"를 더한다. 러그와 이펙트 소제목 앞에 둔다.
- 상점에는 살 수 있는 것(`gems`, `gold`)과 업적으로 열리는 것(`achievement`)만 진열한다. 명예, 랭킹, 고양이, 패스 아이템은 상점에 두지 않고 프로필 꾸미기 화면에서 얻는 방법만 보여 준다.
- 카드 상태(`cosmeticStatus`)를 넓힌다: 장착 중, 장착하기, 보석으로 사기, 골드로 사기, 업적 잠김("'불패의 집사' 업적을 받으면 열려요"), 챕터 잠김(기존). 가격표 `PriceTag`는 이미 골드를 지원한다. 상태 다섯 가지를 고정한 테스트(`tests/screens.collection.shop.test.ts` 102줄 근처)를 새 상태에 맞게 넓힌다.
- 카드 미리보기: 아이콘은 테두리 기본과 함께, 테두리는 기본 아이콘(솜방망이)에 씌워서, 이름표는 "집사" 글자를 얹어서 보여 준다. 지금 미리보기는 `row.kind === 'rug' ? rugPreview : fxPreview`라 새 종류가 모두 이펙트 미리보기로 가므로, 종류별 분기를 더한다. 러그처럼 한 번 구운 그림을 다시 쓰는 캐시를 둔다.
- 구매 버튼과 가격표는 4.4대로 출처에 따라 골드나 보석을 쓴다.
- 블록 서명(`signature`)에 `icon`, `frame`, `plate`와 받은 업적 목록을 넣어 상태가 바뀌면 다시 짓게 한다.

## 9. 그림

- **고양이 아이콘 20개**: `art/units_v2/unit_*.png`(전신 치비, 약 1,270 x 1,240)에서 머리와 윗몸을 정사각으로 잘라 원형에 맞춘다. 새로 그리지 않는다. 5단계 고양이는 머리 위 소품이 잘릴 수 있어 한 장씩 자르는 위치를 정하고, 20장을 한 시트로 모아 확인받는다. 같은 폴더의 `_crop_t45.png`, `_fix_pair.png`, `_lineage.png`는 고양이 그림이 아니니 섞지 않는다. 결과는 `src/assets/img/icon_<id>.webp`(192px 안, `tools/process_art.py`의 `icon_` 규칙)로 두면 `tex('icon_<id>')`로 자동 등록된다.
- **처리 도구**: `tools/process_art.py`에는 `frame_`, `plate_` 접두 규칙이 없어 지금은 건너뛴다(unknown prefix). 두 접두를 더하되, 투명 경계로 잘라 내는 처리(`trim_alpha`)를 하면 가운데가 빈 테두리와 이름표의 중심과 크기가 틀어지므로 잘라 내지 않고 정해진 캔버스 크기 그대로 줄이는 규칙으로 둔다.
- **새 아이콘 컷 12장, 테두리 17장, 이름표 15장**: 새로 그린다. 기존 생성 파이프라인(승인 레퍼런스 `art/style2/v2_m_snow.png`, `v2_t_chef.png`, 무광, 얇은 갈색 외곽선, 흰 스티커 테두리)을 따른다. `art/ref/unit_style.png`는 옛 그림체라 쓰지 않는다.
- 이미지 생성은 유료라, 종류마다 시안 2~3장을 비교 시트로 먼저 보여 드리고 컨펌받은 뒤 본 생성을 한다. 장수가 많아 생성 전에 몇 장을 뽑을지 다시 여쭙는다.
- 테두리는 가운데가 비어 있어야 하고(투명), 이름표는 가운데에 글자 자리가 비어 있어야 한다. 크기 규칙: 테두리 256 x 256(원 안지름 197, 홈에서 104로 줄이면 아이콘 80이 맞는 비율), 이름표 704 x 120(가운데 글자 칸 600 x 72, 홈의 352 폭에서 글자 칸 300). 테두리는 이 캔버스를 넘는 장식을 그리지 않는다(2.2의 위아래 여유가 6과 2뿐이다). 홈과 랭킹에서는 줄여 쓴다.
- 앱 용량: 메뉴 그림은 시작할 때 모두 읽어 둔다(`loadImages`, 지금 `src/assets/img` 169개 약 4.3MB). 새 그림 약 64장이 WebP로 장당 20~40KB면 2~3MB, 지금의 약 60%가 는다. 시작 시간이 눈에 띄게 늘면 꾸미기 그림(`icon_`의 새 컷, `frame_`, `plate_`)은 꾸미기 화면이나 랭킹을 처음 열 때 읽게 바꾼다. 구현 때 재 보고 정한다.

## 11. 나눠서 하기

| 단계 | 내용 | 서버 배포 |
|---|---|---|
| 1 | 저장 필드, 카탈로그, 홈 상단 새 모양, 꾸미기 화면, 고양이 아이콘 20개, 기본 테두리와 이름표, 환불 회수를 모든 종류로 넓히기 | 없음 |
| 2 | 상점 꾸미기 블록에 골드, 보석 아이템, 업적 해금과 명예 업적 지급 | 없음 |
| 3 | `setLook`, `look` 필드, 랭킹 줄 아이콘, 프로필 카드 | 함수와 규칙 |
| 4 | `settleWeek`, `claimGrants`, 랭킹 보상 지급 | 함수 |

- 1과 2는 그림이 기본 몇 장뿐이어도 돌아가게 만들고, 새 그림은 컨펌이 나는 대로 채운다.
- 3과 4는 서버를 먼저 배포하고 앱을 낸다. 서버 안에서는 `firestore.rules`를 먼저, 함수를 나중에 배포한다(5.2). 옛 앱은 `look`이 없는 행을 그대로 그리고, `look`이 있는 행도 모르는 필드라 무시한다.
- 각 단계 끝에 전체 시험, 헤드리스 Edge로 홈과 꾸미기 화면과 랭킹 화면 사진(한국어, 영어, 긴 이름 12자, 로그인 전과 후)을 찍어 겹침과 잘림을 확인한다.
- 비공개 테스트 중이라 앱에 넣으려면 versionCode를 올린 새 AAB가 필요하다.

## 13. 결정 사항

2026-11-25 사용자가 아래 권장안을 모두 확정했다. 7번은 "추후에 추가될 수 있음"을 덧붙였다(4.5에 대비를 적음).


1. 경험치를 이름표 아래 얇은 줄로 남기는 안(2.2)이 괜찮은지. 숫자(48 / 120)는 안 보이게 된다.
2. 랭킹 시즌을 주간(월요일 0시)으로 하는 안(5.3)이 괜찮은지. 한 달 단위로 하려면 서버에 기간 계산을 새로 넣어야 한다.
3. 주간 보상 구간(1위, 2~3위, 4~10위, 11~100위)과 같은 구간을 다시 하면 보석 100으로 바뀌는 규칙.
4. 명예 업적 5개와 업적 해금 14개의 짝(8장).
5. 골드와 보석 가격(8장). 골드 수입 수치는 문서의 추정치라 실제 테스터 기록이 쌓이면 다시 맞춘다.
6. 새 그림 장수(아이콘 12, 테두리 17, 이름표 15)를 처음부터 다 만들지, 1단계는 적게 시작할지.
7. 꾸미기를 현금 상품 묶음에도 넣을지. 처음 판은 넣지 않는다. 추후에 추가될 수 있어서, 환불 회수는 1단계에서 새 종류까지 되돌리게 만들어 둔다(4.5). 추가할 때 남는 일은 카탈로그 묶음과 Play 인앱 상품 등록, 현금 상품 11종을 고정한 테스트(`tests/meta.rules.test.ts`) 수정이다.
8. 다른 유저의 꾸미기를 랭킹 상위 100에서만 보여 주는 범위(6장)로 충분한지.
9. 주간 랭킹 보상을 52주 동안 앱을 켜지 않으면 사라지게 하는 규칙(5.3).
10. 기본 고양이 16종 아이콘을 처음부터 모두 쓰게 하는 안(4.3). 일부를 보상으로 돌리려면 기준을 새로 정해야 한다.

## 14. 확인 못 한 것

- 첫 줄 높이를 바꾸지 않아도 테두리와 레벨 띠가 실제 화면에서 겹치지 않는지는 만들고 나서 사진으로 확인해야 한다. 2.2의 여유(위 6, 아래 2)는 코드의 좌표로 계산한 값이다.
- 판이 끝날 때 그 판에서 각성시킨 수호신 id를 어디서 꺼낼지는 구현 때 판 결과 코드에서 찾는다.
- 사람 기준으로 명예 업적에 며칠이 걸리는지는 업적 문서도 확인하지 못한 상태다.
