# 설계 결정 기록

> 기록일 2026-10-06 · 기준: [기획서 v1.0](기획서_GDD.md), [전투 규칙 명세 v1.0](명세_전투규칙.md) (D-41부터는 기획서 v1.1 · 명세 v1.2 기준)
> 한 행은 결정 하나다. 무엇을 정했고, 무엇을 대체했고, 왜 그랬고(근거), 무엇이 드는지(대가)를 적는다.
> 이 기록은 설계가 독자적으로 만들어진 경위를 보여 주는 증빙이기도 하다. 선행작과 겹칠 수 있는 곳에서 어떻게 갈라졌는지가 근거 열에 남는다.

## 읽는 법

| 표기 | 뜻 |
|---|---|
| 01 §n · 02 §n · 03 §n | `docs/research/` 세 문서의 해당 절 ([장르](research/01_장르_레퍼런스_분석.md) · [수익화](research/02_수익화_유통_분석.md) · [연출](research/03_연출_UX_사운드_가이드.md)) |
| [실현 n] | 실현 가능성·법무 비평의 n번째 발견 |
| [재미 n] | 재미·밸런스 비평의 n번째 발견 |
| [수익 n] | 수익화 비평의 n번째 발견 |
| [실현·재미·수익 아이디어: 이름] | 해당 비평이 "빠진 것"으로 제안한 항목 |

- 비평 3건의 원문은 저장소 밖(워크플로 출력)에 있다. 이 기록은 발견 번호로 인용하고, 번호와 제목은 아래 "인용한 비평 발견"에 모아 두었다.
- **비평의 수치는 비평자의 종이 모델에서 나왔다.** 비평자도 `npm run sim`이 아니라고 밝혔다. "근거" 열의 수치는 방향을 정한 이유이지 검증된 결과가 아니다. 최종 값은 봇 시뮬레이션으로 정한다.
- 근거를 적을 때 리서치의 확인 수준(V 확인 / E 추정)은 원문을 따른다. 리서치에 근거가 없는 결정은 대가 열에 그렇게 적었다(D-02).

## G. 검토했지만 1.0에 넣지 않은 제안
