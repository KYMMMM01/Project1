# 기능 지도

게임의 화면과 기능을 플레이어 입장에서 모으고, 각각을 주소(URL)와 디버그 훅(`window.__dbg`)으로 여는 방법을 적은 문서다. 화면 확인과 캡처는 이 문서와 `tools/edge` 로 한다. `tests/docs.featureMap.test.ts` 가 이 문서의 `__dbg` 이름과 코드의 훅을 서로 대조하므로, 훅을 더하거나 빼면 여기도 고쳐야 테스트가 통과한다.

## 1. 한 줄로 화면 찍기

```powershell
node tools/edge/shot.mjs shop-frame "?scene=home&tab=shop&fresh=1" --dist .shots/dist-qa --js "window.__dbg.meta.finishRuns(3)" --scroll "/^테두리$/"
```

- 헤드리스 Edge(소리 끔)를 띄워 화면을 열고, 저절로 뜨는 팝업을 모두 정리한 뒤, 단계(`--js`, `--scroll`, `--tap`, `--wait`)를 적은 순서대로 하고 `.shots/edge/<이름>.png` 를 남긴다. 페이지 오류(`window.__errors`)도 출력한다.
- `--dist <폴더>` 는 그 폴더의 빌드를 띄운다. 폴더가 없거나 `src` 의 어떤 파일보다 오래됐으면 먼저 빌드한다(웹 빌드, 약 10초). 빼면 개발 서버(`GAME_PORT`, 기본 5173)를 쓴다.
- `--js` 다음에는 정리를 한 번 더 한다. 판 끝내기나 해금 같은 치트는 새 해금 알림과 레벨업 팝업을 부르기 때문이다.
- 저장 데이터는 포트별 프로필 폴더(`.shots/edge/profile-9351`)에 남아 다음 실행으로 이어진다. 빈 저장으로 시작하려면 주소에 `fresh=1` 을 넣는다.
- `debug=1` 은 빠져 있으면 자동으로 붙는다. 빌드에서는 이 값이 있어야 디버그 훅이 생긴다.
- 스크립트가 필요하면 `tools/edge/lib.mjs` 의 `withGame`, `settle`, `scrollTo`, `tapText`, `textCentre` 를 쓴다. `withGame` 은 브라우저와 빌드 서버를 항상 닫는다(남은 헤드리스 Edge 는 CPU 를 계속 먹는다).

함정:

- Git Bash 는 `"/^테두리$/"` 처럼 `/` 로 시작하는 인자를 파일 경로로 바꾼다. Git Bash 에서는 `MSYS_NO_PATHCONV=1` 을 먼저 설정한다. PowerShell 은 괜찮다.
- `?demo=` 갤러리는 개발 서버에서만 열린다. 빌드에는 들어 있지 않다.
- 소리 판과 진단 페이지(`?scene=sounds`, `?scene=diag`)는 게임도 디버그 훅도 없어서 `shot.mjs` 로 찍지 못한다(40초 뒤 오류). `cdp.mjs` 의 `launch` 로 직접 연다.
- 일반 전투(`sandbox` 없이)는 레이저 첫 사용 안내가 뜬다. 안내 없이 찍으려면 `sandbox=1` 을 넣는다.
- 샌드박스 전투는 전투마다 설명서 기록을 새로 만든다. 홈에서 정리하고 전투로 넘어갔다면, 전투가 열린 뒤 정리를 다시 한다.

## 2. 좌표

| 공간 | 뜻 | 어디서 |
|---|---|---|
| 디자인 | 가로 720, 세로 1280에서 1600 | 화면 코드의 모든 좌표 |
| Pixi 전역 | 캔버스 왼쪽 위 기준 CSS 픽셀(디자인 곱하기 `game.scale`) | `getBounds()`, `getGlobalPosition()` |
| 클라이언트 | 브라우저 창 기준 CSS 픽셀, 클릭이 받는 단위 | 캔버스 위치 더하기 Pixi 전역 |
| 스크린샷 | 클라이언트 곱하기 2(`deviceScaleFactor`) | `b.shot` 이 만든 PNG |

- `__dbg.texts`, `textCentre`, `tapText` 가 돌려주는 위치는 모두 클라이언트 픽셀이라 그대로 `b.click` 에 넣는다.
- 디자인 좌표는 `__dbg.toClient(x, y)` 로 바꾼다.
- 스크린샷에서 잰 픽셀은 2로 나눠야 클릭 위치가 된다.
- 마우스 휠은 디자인 픽셀만큼 움직이고 애니메이션이 있어 캡처가 어긋난다. 스크롤은 `scrollTo` 를 쓴다.

## 3. 화면별 여는 법

빌드에서는 모든 주소에 `debug=1` 이 필요하다(`shot.mjs` 와 `openGame` 은 알아서 붙인다). 해금 조건은 `src/meta/data/schedule.ts` 에 있다. 판 수 1이면 고양이, 미션, 상점, 패스, 순찰, 2배속이 열리고, 3이면 간식, 저금통, 꾸미기가 열린다. 챕터 1을 깨면 일일 도전, 소탕, 컵, 골드 던전이, 챕터 2를 깨면 무한 모드가 열린다. 판은 `__dbg.meta.finishRuns(n)` 으로 채운다.

- 기본값은 챕터 1 승리라서 첫 판부터 챕터 1 해금(일일 도전 등)이 같이 열린다. 판 수만 채우려면 `__dbg.meta.finishRuns(n, { victory: false })` 를 쓴다.
- 챕터는 1부터 이어서 센다. 무한 모드는 `__dbg.meta.finishRuns(1)` 다음에 `__dbg.meta.finishRuns(1, { chapter: 2 })` 를 해야 열린다.
- 한 번에 다 열려면 `__dbg.meta.unlockAll()` 을 쓴다(집사 패스의 3배속만 빼고).

| 화면 | 주소 | 디버그 훅 | 비고 |
|---|---|---|---|
| 타이틀 | `?` 만(`scene` 없이) | | `titlems=N` 이면 N 밀리초 뒤 저절로 넘어감, `pgs` 는 구글 계정 줄 흉내 |
| 튜토리얼 전투 | `?fresh=1&notitle=1` | | 새 프로필의 첫 화면. `?scene=battle&mode=tutorial&sandbox=1` 도 됨 |

## 4. 주소 매개변수

| 매개변수 | 값 | 뜻 |
|---|---|---|
| `debug` | 있기만 하면 | 디버그 훅을 켬(개발 서버는 늘 켜짐, 상점용 앱 빌드는 `VITE_DEBUG=on` 일 때만) |
| `scene` | home, battle, lab, sounds, diag | 첫 화면. 어떤 값이든 타이틀을 건너뜀 |
| `tab` | shop, cats, battle, missions, pass | `scene=home` 과 함께. 잠긴 탭은 잠김 안내가 보임 |
| `fresh` | 있기만 하면 | 저장과 디버그 시계를 지우고 시작 |
| `notitle` | 있기만 하면 | 타이틀 건너뜀 |
| `titlems` | 밀리초 | 타이틀이 저절로 넘어가는 시간 |
| `pgs` | on, off, wait | 타이틀의 구글 계정 상태 흉내 |
| `lang` | ko, en | 언어 |
| `lean` | 1, 0 | 가벼운 모드 강제 켜기, 끄기 |
| `sp` | 1, 0 | 스킬 켜기, 끄기 |
| `adfail`, `adfast`, `iapfail`, `iapcrash` | 1 | 개발용 광고, 결제 흉내(광고 실패, 짧은 광고, 결제 실패, 결제 직후 앱 종료) |
| `laserguide` | 1 | 샌드박스 전투에서도 레이저 안내를 보임 |
| `demo`, `page`, `keep`, `skip` | | 갤러리 전용(개발 서버) |

전투 주소(`scene=battle` 또는 `lab`) 전용:

| 매개변수 | 값 |
|---|---|
| `mode` | tutorial, chapter(기본), daily, endless, gold |
| `chapter` | 1에서 5 |
| `stake` | 집사 레벨 0에서 5 |
| `seed` | 정수, 기본 7 |
| `level` | 기본 고양이 레벨 1에서 10 |
| `runs` | 지금까지 판 수 0에서 999 |
| `sandbox` | 1이면 진짜 저장과 설명서 진도를 건드리지 않음 |
| `rug`, `fx` | 깔개와 이펙트 테마 id |

## 5. 디버그 훅(`window.__dbg`)

`__dbg.help()` 가 지금 붙어 있는 훅과 함수 이름을 돌려준다. 어떤 훅은 그 화면이 만들어진 뒤에 생긴다.

| 훅 | 생기는 때 | 주요 함수 |
|---|---|---|
| `__dbg.game`, `__dbg.scenes` | 항상 | 게임과 씬 관리자 그 자체 |
| `__dbg.toClient` | 항상 | 디자인 좌표를 클라이언트 픽셀로 |
| `__dbg.texts` | 항상 | 정규식에 맞는 글자들, 맨 위 것부터, 클라이언트 상자와 함께. 스크롤에 가려졌거나 캔버스 밖이면 `inView` 가 false(`textCentre`, `tapText` 는 이런 글자를 건너뜀) |
| `__dbg.scrollTo` | 항상 | 그 글자를 품은 스크롤 목록을 굴려 글자를 위쪽에 둠 |
| `__dbg.help` | 항상 | 훅 목록 |
| `__dbg.crumbs`, `__dbg.gpuMemory`, `__dbg.lean`, `__dbg.analytics` | 항상 | 진단용 |
| `__dbg.meta` | 부팅 뒤 | addGold, addGems, addTickets, addCards, addChest, finishRuns, unlockAll, advance, startPending, reset, profile |
| `__dbg.codex` | 부팅 뒤 | open, close, state, met, progress |
| `__dbg.routine` | 부팅 뒤 | openSettings, openCalendar, scrollSettingsTo, popups, markSeen |
| `__dbg.home` | 홈에 들어간 뒤 | goTab, shell(startRun, pointAt 등), scene |
| `__dbg.shop` | 상점 탭이 만들어진 뒤 | jumpTo, actions, rebuilds |
| `__dbg.collection` | 상점이나 고양이 탭이 만들어진 뒤 | openShop, openUnit, openOdds, revealChest, showRewards |
| `__dbg.battle` | 전투가 열린 뒤 | skipToWave, win, lose, give, board, put, relic, spawn, boss, step, hold, setSpeed 등 |
| `__dbg.lessons` | 전투 화면이 있는 동안 | card, hints, progress, tutorial |
| `__dbg.director`, `__dbg.spStage`, `__dbg.spRings` | 전투 중 | 연출 통계 |
| `__dbg.audio` | 소리 엔진이 켜진 뒤 | stats, report, music, mix 등 |
| `__dbg.ui`, `__dbg.fx`, `__dbg.platform` | 갤러리에서 | 갤러리 조작 |

## 6. 저절로 뜨는 것과 정리

`__dbg.routine.markSeen()`(lib 의 `settle`)가 아래를 모두 막고, 이미 뜬 팝업을 닫은 뒤, 아직 열려 있거나 대기 중인 팝업 수를 돌려준다. 치트로 해금이나 레벨이 바뀌면 다시 불러야 한다.

| 저절로 뜨는 것 | 조건 | 정리 |
|---|---|---|
| 어서 와요(돌아온 보상) | 며칠 쉬고 들어옴 | 이번 세션에 보인 것으로 침 |
| 출석 달력 | 판 수 1 이상, 오늘 받을 보상이 있음 | 오늘 보인 것으로 침(날짜가 바뀌면 다시) |
| 보석 패스 일일 보석 | 보석 패스 보유 | 이번 세션에 보인 것으로 침 |
| 계정 레벨 업 | 레벨이 오름 | 지금 레벨까지 본 것으로 침 |
| 새로 열렸어요 | 기능이 해금됨 | 지금 해금까지 본 것으로 침 |
| 첫 만남 카드(알겠어요) | 전투에서 처음 보는 것 | 설명서 주제를 모두 읽은 것으로 침(샌드박스 전투는 그 전투가 열려 있을 때 부른 경우만), 이미 뜬 카드는 `settle` 이 버튼을 누름 |

정리하지 않는 것: 이어서 할까요(`startPending` 을 쓰지 않으면 안 뜸), 상자 다시 열기(저장의 `reveals` 가 비어 있으면 안 뜸), 레이저 첫 사용 안내(`sandbox=1`), 패스 탭의 시즌 끝 경고, 온라인 계정의 랭킹 보상과 클라우드 저장 선택.
